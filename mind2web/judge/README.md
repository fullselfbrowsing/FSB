# WebJudge local protocol and CLI transport

New runs use **`scorefield-v2`**, a versioned local fork of OSU's evaluator. `upstream/` remains byte-identical to commit `f0d805ee0e9e0b3ea70911e45e5264b72968f3dc`; [VENDORED.md](upstream/VENDORED.md) lists its hashes. The local protocol retains all three prompt templates literally, key-point normalization, image encoding, source order, threshold 3 and the first 50 qualifying images. Tests compare the prompt literals and ordering with the vendored source. Historical runs require their archived source/environment; the new runner refuses their output fingerprints.

The shared parser reads exactly one final standalone `Score: 1` through `Score: 5` field. Markdown emphasis and list prefixes are accepted. Prose containing “Score” cannot supply the value; duplicate fields, invalid ranges, missing separators, fenced responses and trailing prose are rejected. Final `Status` is exactly `success` or `failure`, optionally quoted. Every provider response is stored unchanged, including whitespace; parsed values and response hashes are additional fields. This is a disclosed parser change, not an assertion that upstream scoring is unchanged.

New runs judge with Claude Opus 5.5: `claude -p` from the pinned CLI in `config/model-family.json`, `--model claude-opus-5-5 --effort medium`, `--max-turns 1`, no built-in tools or MCP servers, no settings, hooks, slash commands or session persistence, a temporary system-prompt file, and the task text plus ordered images as one stream-json user message. Its environment is allowlisted, so it inherits no operator Claude Code session or API key and runs on the subscription login. Any reported tool or MCP server invalidates the call. Claude Code adds its own short system preamble and environment note around the WebJudge prompt. The historical Codex engine below is retained for reproducibility.

Codex uses `codex exec -m gpt-6.1-sol`, medium effort, ordered `-i` images and a temporary system-instructions file. User configuration, rules, project documents, web search, shell and patch tools are disabled. Any observed command, MCP, web-search or file-change event invalidates the call. The transport inspects actual image bytes and uses the unchanged JPEG payloads. Subscription CLIs do not provide the upstream temperature/token-limit controls or an identical API system envelope; requested settings and actual usage are retained. These substitute judgments are unverified and not human calibrated.

The full matrix has six jobs: official and strict, three passes each, on one engine (Claude for new runs; the historical full run used Codex). `strict` removes `TASK_COMPLETE -> ANSWER:` action text while retaining every screenshot. One job runs at a time with 10 task workers, engine concurrency 10 and a process-safe global cap of 10 judge CLI processes. Collection must finish before judge fingerprints are frozen.

```sh
./run_judges.sh /absolute/new-run/trajectories /absolute/new-run/judge /absolute/new-run/task-ids.json
```

Each job writes `config.json`, append-only `results.jsonl` and correlated `usage.jsonl`, `summary.json`, and immutable valid-stage cache entries in `stages/`. Call records identify job, task, stage, image index/hash, prompt hash, call ID, timestamps, actual process spawn and usage. Cache keys bind the full configuration, trajectory, prompt, model and effort. Every restart checks all inputs, evaluator sources and saved stage integrity before calls. Valid stages and normal terminal verdicts are reused. Only absent or infrastructure-pending tasks are retried; normal format errors are not silently judged again.

Image/final format failures permit at most three identical attempts; transient transport failures permit at most two attempts. Missing trajectories and persistent task-format errors count zero in the full 300-task denominator. Infrastructure errors have a null label and remain pending, so a provisional pass cannot be declared complete. Usage retry failures and task-level format errors are reported separately. Reports include all six rates, three-pass means/ranges, majority labels, disagreements, usage and latency; benchmark filter-rubric labels remain distinct from literal-goal human review.

The durable model-family circuit (`--family claude` for new runs) is shared with collection. A finished call whose `rate_limit_event` shows the five-hour window at 90% or the seven-day window at 97% records a `headroom` pause until that window's reset; it reopens without a probe. It is checked after both queues immediately before every spawn, including retries. Quota opens it immediately: an evidenced reset adds a 60-second margin; otherwise delays are 30 minutes, 1 hour, 2 hours, 4 hours and then 6 hours. A due circuit permits one real pending-call probe, with at most six quota probes per rolling 24 hours. Three consecutive transport failures open bounded 60/120/300/600/900-second backoff with at most 12 probes per rolling day. Rate limiting follows bounded Retry-After. Late calls cannot close a newer circuit generation; successful recovery preserves rolling probe history. A live probe owner prevents duplicate probes even after the lease time. Status reads never spend a probe.

The non-Python collector uses the stdin JSON bridge:

```sh
PYTHONPATH=. .venv/bin/python -m om2w_judge.circuit --state /absolute/shared-circuit.json --request-stdin admit
```

Supply `{"scope":"actor:<id>","owner_pid":12345,"lease_seconds":1260}` on stdin with the long-lived collector PID. Successful admission returns a permit; exit 75 means wait. `success` and `failure` take that `permit`, with `error` and optional `kind` for failure. If an admitted actor returns `model_spawn_requested:false`, call `abandon` with its permit: only the matching current half-open probe is returned to the same open gate and its unused probe-budget entry removed. Stale/closed permits do nothing; actual configuration failures still block normally. Keep errors out of command-line arguments. `status` is read-only with respect to dispatch.

Authentication/configuration errors block indefinitely until repaired. Explicit operator recovery uses `operator-recover` with stdin fields `acknowledgement:"operator_repaired_authentication_or_configuration"`, a nonempty recorded `reason`, and the current `expected_generation` and `expected_error_sha256` from status. It authorizes one pending-call probe; it does not clear quota history, backoff or a quota gate. No synthetic availability model calls are made.
