## Decisions Made

- `parseValue` refuses secret and endpoint keys with `SETTING_PROTECTED_KEY` before it reads `raw` (D-10/D-11). Plan 02's `planWrite` checks the class first anyway, so this only adds a second guard.
- Failure sentences match the forms later plans expect:
  - unknown key: `Unknown setting key. Call settings with no arguments to list keys.`
  - protected key: `<key> is read-only over MCP; change it in the FSB Control Panel.`
  - integer: `<key> must be a whole number from <min> to <max>.` (the form plan 03's example uses)
  - enum: `<key> must be one of: <values>.`
  - boolean: `<key> must be true or false.`
  - string: `<key> must be at most <n> characters.`
  - non-string value: `The value for <key> must be a string.`
- Failure objects carry `range` only for integers and `values` only for enums, as the contract says. Booleans and strings carry neither, so plan 02's `Allowed:` clause applies only to integers and enums (plus its own modelName and agentProviderId cases).
- `create()` is strict. Its input must be an array. It throws `TypeError` on:
  - unknown fields, or invalid or duplicate keys
  - an unknown type, class or group
  - a non-string secret or endpoint
  - a field that belongs to another type (min/max outside integers, values outside enums, maxLength outside strings)
  - bad bounds or a default outside them
  - enum values that are empty or duplicated
  - a computed default other than `agentCapRecommendation`

  It copies what it is given, so the caller's objects are never frozen.
- The enum `values` of `modelProvider` reuse the `PROVIDERS` list. `create` copies it into a fresh frozen array per entry.
