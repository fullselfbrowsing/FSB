Wire contract with the extension (implemented by plans 66.1-05/06; this plan must not depend on extension code):
- `mcp:get-settings` payload `{}` (read all) or `{ key }` (read one). `mcp:set-setting` payload `{ key }` or `{ key, value }`. sendAgentScopedBridgeMessage adds agentId, recordingCallId, recordingLeaseMs and, when present, connectionId and recordingRunId; pass `{ timeout: 10_000, includeOwnershipToken: false }`.
- Extension success payloads (bridge resolves with the payload): read-all `{ success: true, settings: {...}, readOnly: [...] }`; read-one `{ success: true, key, value, type, writable, range?, values? }`; write `{ success: true, key, value, previous, changed: [...] }`.
- Extension failure payloads: `{ success: false, code, errorCode, error, key?, range?, values? }` with `code` in SETTING_REQUEST_INVALID, SETTING_UNKNOWN_KEY, SETTING_PROTECTED_KEY, SETTING_VALUE_INVALID, SETTING_PROVIDER_NOT_READY, SETTING_DELEGATED_WRITE_REFUSED, SETTING_UNSUPPORTED, SETTING_STORAGE_FAILED. `error` is value-free.
- An extension without settings support answers with an mcp:error whose payload resolves as `{ success: false, error: 'Unknown MCP message type: mcp:get-settings' }` (mcp-bridge-client.js default arm; bridge.ts sendAndWait resolves resp.payload and logs `error="..."` to stderr).
- MCP-local codes produced by this tool: SETTING_REQUEST_INVALID, SETTING_UNSUPPORTED.

Tool (D-03, D-04, D-07; Claude's discretion resolved here):
- Name `settings`. Description exactly: `Read or change FSB settings. No args returns all; key returns one with its allowed values; key and value sets it. API keys and endpoints are read-only.` (151 characters).
- Params: `key: z.string().optional().describe('Setting name')`; `value: z.preprocess(toWireString, z.string()).optional().describe('New value (string; true/false and numbers accepted)')`, where `toWireString(v)` returns `String(v)` for a boolean or a finite number and returns v unchanged otherwise. No `.max()` (no maxLength keyword on the wire), no enum of keys (SC4), no bare `z.number(`.
- Verified JSON Schema (RESEARCH Pattern 1): `{"type":"object","properties":{"key":{"type":"string","description":"Setting name"},"value":{"type":"string","description":"New value (string; true/false and numbers accepted)"}},"additionalProperties":false,"$schema":"http://json-schema.org/draft-07/schema#"}`.
- Constants: `SETTINGS_TIMEOUT_MS = 10_000`, `SETTINGS_KEY_MAX = 64`, `SETTINGS_VALUE_MAX = 2048`, `UNSUPPORTED_SETTINGS_ERROR = /^Unknown MCP message type: mcp:(get-settings|set-setting)$/`.
- Handler flow:
  1. `!bridge.isConnected` -> `mapFSBError({ success: false, error: 'extension_not_connected' })`.
  2. value defined and key undefined -> local SETTING_REQUEST_INVALID ('value needs a key. Call settings with key and value.'), no bridge call.
  3. key longer than SETTINGS_KEY_MAX or value longer than SETTINGS_VALUE_MAX -> local SETTING_REQUEST_INVALID (text names the limit only), no bridge call.
  4. Read (value undefined): send `mcp:get-settings` with `{}` or `{ key }`. Unsupported reply -> local SETTING_UNSUPPORTED ('This FSB extension does not support settings yet. Update the FSB extension.'). Failure -> `mapFSBError(result)`. Success -> compact output.
  5. Write: preflight `mcp:get-settings { key }`. Unsupported -> SETTING_UNSUPPORTED (the value never left the process). Preflight success with `writable === true` -> send `mcp:set-setting { key, value }`. Preflight failure with code SETTING_UNKNOWN_KEY, or success with writable false -> send `mcp:set-setting { key }` WITHOUT value (the extension refuses and logs the refusal). Any other preflight failure -> `mapFSBError(preflight)` without sending a write. A set reply that is the unsupported error -> SETTING_UNSUPPORTED.
  6. Thrown errors from the bridge (not connected, timeout) are caught and rendered with `mapFSBError({ success: false, error: <message> })`; bridge messages contain only the type and id, never the value.
  7. Compact output: `{ content: [{ type: 'text', text: JSON.stringify(body) }] }` with no indent. body is built from whitelisted fields only: read-all `{ settings, readOnly }`; read-one `{ key, value, type, writable }` plus `range` and/or `values` when present; write `{ key, value, previous, changed }`.
  8. Local SETTING_ failures are rendered with `mapFSBError({ success: false, code, errorCode: code, error, recoveryHint })`, with recoveryHint 'Update the FSB extension, or change the setting in the FSB Control Panel.' for SETTING_UNSUPPORTED and 'Call settings with only a key to see its type and allowed values, or with no arguments to list every setting.' for SETTING_REQUEST_INVALID. Extension SETTING_ failures are passed to mapFSBError whole; their `error` already ends with any `Allowed:` clause (plan 66.1-02) and they carry their own recoveryHint (plan 66.1-05).
  9. The handler never calls console.* with args, key or value.
