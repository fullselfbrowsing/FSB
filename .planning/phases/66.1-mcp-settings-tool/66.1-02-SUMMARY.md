# Phase 66.1 Plan 02: Settings write planner and control-panel parity Summary

**`FsbSettingsSchema.planWrite` now makes every MCP settings write decision. It checks the key, then the class, then parses the value strictly, then applies the D-15 provider rules, with value-free errors that state what is allowed. `Config.DEFAULT_MODELS` is the single default-model map, now shared with `validateAndCorrectModel`. Tests pin the schema to every control-panel writer, all three default copies and every panel bound.**

## Accomplishments

- **`Config.DEFAULT_MODELS`:** a frozen static set right after the class body, with the seven pairs.
  - `validateAndCorrectModel` now reads it through `const defaultModels = Config.DEFAULT_MODELS;`. Everything else in that method is unchanged, including the empty-name `console.warn` and the `|| 'grok-4-1-fast'` fallback.
  - The gemini default literal appears once in the file. `Config.defaults` is unchanged.
- **`planWrite(key, raw, stored, ctx)`** checks in this order:
  1. Unknown key: `SETTING_UNKNOWN_KEY`.
  2. Secret or endpoint: `SETTING_PROTECTED_KEY`, before `raw` is touched. A Proxy trap in the tests proves `raw` is never read.
  3. Missing value: `SETTING_REQUEST_INVALID`. Otherwise the value goes through `parseValue`.
  4. Provider rules:
     - **`modelProvider`, new provider:** a hosted provider needs its API key stored, and `custom` needs `customEndpoint`. The patch also sets `modelName` to `Config.DEFAULT_MODELS[p]`.
     - **`modelProvider`, same provider:** no readiness check, and `modelName` is never reset.
     - **Hosted `modelName`:** must be a built-in id or a cached id, with no network call. The failure lists up to 25 ids, plus `(+N more)`.
     - **`providerKind=agent`:** needs a shipped `agentProviderId`.
     - **`agentProviderId`:** must be shipped or `""`. Clearing it while `providerKind` is `agent` is refused.
  5. No-op rule: when every patch key is stored with an equal value, the write is a no-op. Writing to an absent key is still a real write.
- **Helpers on every instance:**
  - `HOSTED_PROVIDERS`
  - `PROVIDER_API_KEY`: matches `getApiKey`, proven by a behavioural parity case.
  - `knownModelIds`: the built-in ids from the `config` singleton, read at call time, followed by the discovered ids, without duplicates.
  - `discoveredIdsFromCache`: the `getDiscoveredModelIds` rule applied to the stored `fsbDiscoveryCache` object (Pitfall 7).
  - `formatAllowed`
- **Sample sentences**, which `errors.ts` (plan 03) passes through unchanged:
  - `maxIterations must be a whole number from 50 to 500. Allowed: 50 to 500.`
  - `sttProvider must be one of: browser, whisper. Allowed: browser, whisper.`
  - `agentProviderId is not a shipped agent provider. Allowed: "", claude-code, grok-build.`
  - `modelName is not a known xai model. Refresh models in the FSB Control Panel if it is new. Allowed: grok-4-1-fast, …, disc-19 (+11 more).`
- **Parity tests:**
  - **D-09 inventory:** `extractSaveSettingsKeys` reads the 31 `saveSettings` keys. With the 4 other writers they equal the 35 schema keys. The test also checks:
    - `EXCLUDED_FROM_SCHEMA` (4 keys, each with a reason)
    - that the extra writers still exist
    - a self-check: injecting `fsbParityProbe: true,` is reported as an extra key
  - **D-12 defaults:** compared against `Config.defaults`, `init-config.js` (run through its production branch) and `options.js` `defaultSettings`. 75 copy values are equal. `KNOWN_DEFAULT_DIVERGENCES` holds exactly `showSidepanelProgress` and `serverUrl`, each pinned exactly and paired with its proof line.
  - **D-14 bounds:** checked against the six stepper `data-min`/`data-max` pairs, the retention, trigger-cap and agent-cap clamps, the `agent-cap-recommendation.js` module, the `sttProvider` literals and the seven provider ids.
  - **Tripwire:** guards the `getDiscoveredModelIds` rule.

## Decisions Made

- **Provider rules read the stored value only when it is a string.** Otherwise they use the effective default (`currentText`), matching `fsbReadAuthoritativeProviderConfig`. So stored `modelProvider: 7` with a write of `xai` makes `xai` explicit, and `previous` reports the stored 7.
- **Cases the interface left open** (I chose to fail closed in each):
  - A `modelName` write while the stored provider is outside the seven gets `SETTING_PROVIDER_NOT_READY`, without repeating the stored value.
  - A `modelProvider` value that is not hosted, `custom` or `lmstudio` (possible only in a fixture schema) gets the same code.
- **Sentences** (not fixed by the interface):
  - an unshipped agent id: `agentProviderId is not a shipped agent provider.`
  - clearing the agent id while `providerKind` is `agent`: `Set providerKind to api before clearing agentProviderId.`
  - an unknown stored provider: `Choose a model provider in the FSB Control Panel first.`
- **`changed` lists every patch key, unless the whole write is a no-op** (as the interface says). A provider change whose new default equals the stored `modelName` still reports both keys.
- **`formatAllowed` edge cases:**
  - An empty list with a positive `omitted` renders `(+N more)`.
  - A non-finite or non-numeric range renders nothing.
  - Values that are neither strings nor finite numbers are dropped.
