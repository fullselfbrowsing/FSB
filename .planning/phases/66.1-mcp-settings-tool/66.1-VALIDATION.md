## Sampling Rate

- **After every task commit:**
  - Run the task's `<automated>` command.
  - Also run the pin suites for every file the task edits (table below, from RESEARCH Pitfall 6). For `options.js`, `mcp-tool-dispatcher.js` and `mcp-bridge-client.js` edits, also run the regression sweep against the Wave 0 baseline. The sweep selects tests by basename, so at HEAD it runs 112, 38 and 27 of 411 tests for those files (87 for `config.js`).
- **After every plan wave:**
  - Run all new suites present so far, plus `mcp-version-parity`, `mcp-tool-routing-contract`, `capability-mcp-surface`, `tool-definitions-parity`, `mcp-session-recorder`, `mcp-session-recorder-journal`, `delegation-phase-contract` and `npm run test:mcp-smoke:tools`.
  - Run each new suite once more under `npx --offline -y node@20`.
- **Before `/gsd:verify-work` (phase gate):**
  - `npm run validate:extension && npm test` is green.
  - `npm run test:mcp-smoke:tools` is green.
  - The `mcp/` footprint audit (row `BOTH-b`) is clean.
  - All four new suites pass under Node 20.
  - The three showcase crawler files are restored.
  - A red `EADDRINUSE` in the chain means the chain stopped early and later suites never ran. Since the 2026-10-12 main merge, the whole chain passes with the native-host hub on 7225, so a red port-bound suite is a real failure.
- **Max feedback latency:** 60 seconds per task check.
