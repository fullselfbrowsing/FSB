# Phase 66.1 Plan 05: Settings routes in the service worker Summary

**The service worker now answers the `settings` tool: `mcp:get-settings` reads every setting (masked secrets, origin-only endpoints, effective defaults with the awaited agent-cap recommendation) or one key with its constraints, and `mcp:set-setting` writes one key, or the provider pair in one `chrome.storage.local.set`, through `FsbSettingsSchema.planWrite` under a write lock. Delegated agent runs and unidentified sessions are refused through the bridge client's real fail-closed detector, every write outcome gets an `automationLogs` line without the submitted value, and both types reach the dispatcher only through `MCPBridgeClient._routeMessage`.**

## Accomplishments

- **Route table** (`MCP_PHASE199_MESSAGE_ROUTES`):
  - `'mcp:get-settings': { routeFamily: 'settings', handler: handleGetSettingsMessageRoute }`
  - `'mcp:set-setting': { routeFamily: 'settings', handler: handleSetSettingMessageRoute }`
  - Both sit after `'agent:status'`, under a Phase 28/31-style comment: internal routes, not `TOOL_REGISTRY`, MCP bridge only (D-06).
  - `getMcpRouteContracts()` reports both automatically.
- **Handler block** sits after `handleGetLogsMessageRoute`, well after `dispatchMcpMessageRoute`, so no recorder pin moves. The block adds:
  - `_withSettingsWriteLock`, on its own `_settingsWriteChain`
  - `SETTING_RECOVERY_HINTS` (frozen) and `_settingsFailure`. Every `SETTING_*` failure either route returns goes through it.
  - `_resolveSettingsSchema`: a lazy lookup of `globalThis.FsbSettingsSchema`
  - `_readSettingsStorage` / `_writeSettingsStorage`: promise form, guarded
  - `_settingsCurrentProvider`
  - `_buildSettingsContext`, which builds `ctx`:
    - **agent cap:** `await`s `FsbAgentCapRecommendation.getRecommendedAgentCap()` (D-12), inside try/catch
    - **agent ids:** `isShippedAgentId` / `shippedAgentIds` come from `FsbDelegationProviders` (`ids().filter(isShippedId)`)
    - **model ids:** `discoveredModelIds` comes from the persisted `fsbDiscoveryCache` (Pitfall 7). No fetch.
  - `_isHostedSettingsProvider`
  - `_logSettingsWrite`
  - the two handlers
- **`mcp:get-settings`:**
  - **No key:** returns `{ success, settings, readOnly }`.
  - **With a key:** returns `{ success, key, value, type, writable }`, plus `range` or `values` where they apply:
    - hosted `modelName`: the built-in ids, then the cached ids, capped at 25
    - `agentProviderId`: `""` followed by the shipped ids
  - **Failures:**
    - unknown or malformed key: `SETTING_UNKNOWN_KEY`, labelled with `safeKeyLabel`
    - no schema: `SETTING_UNSUPPORTED`
    - storage error: `SETTING_STORAGE_FAILED`
  - Reads never write and are not logged (D-18: reads are journaled by recording only).
- **`mcp:set-setting`** runs these steps in order:
  1. Object payload, else `SETTING_REQUEST_INVALID`.
  2. Schema, else `SETTING_UNSUPPORTED`.
  3. **D-20 gate**, before the value is read. The write is allowed only when all of these hold:
     - `agentId` is a non-empty string
     - the client has `_isDelegationScopedInbound`
     - `_isDelegationScopedInbound('mcp:set-setting', payload)` returns exactly `false` (the call is wrapped in try/catch)

     Anything else gets `SETTING_DELEGATED_WRITE_REFUSED`.
  4. Inside the lock:
     - read the schema keys
     - build `ctx`
     - call `planWrite`
     - on failure, return the typed failure with `key`, plus `range`/`values` when present
     - otherwise write `plan.patch` in **one** `chrome.storage.local.set` (skipped when the patch is empty); a rejected write gets `SETTING_STORAGE_FAILED`
     - return `{ success, key, value, previous, changed }`
- **D-18 lines** (fire-and-forget; written whether or not session recording is on):
  - accepted: `info('MCP settings write', { key, previous, value, changed, client, at })`
  - refused: `warn('MCP settings write refused', { key: safeKeyLabel or '[invalid]', code, client, at })`

  The submitted value never reaches a log, an error string or a console call. Refusals decided inside the MCP process remain the accepted limit T-66.1-23 (plan 66.1-03).

### Small additions within the interface (no behaviour risk)
