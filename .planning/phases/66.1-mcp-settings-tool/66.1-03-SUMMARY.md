# Phase 66.1 Plan 03: MCP settings tool, wire types and SETTING_ error rendering Summary

**One new `settings` MCP tool, registered for every runtime and kept out of TOOL_REGISTRY. It reads all settings, reads one key, or writes one key straight through the agent-scoped bridge, with no queue. A write reads the key first and sends the value only when the extension says the key is writable. Output is compact JSON. `SETTING_*` failures render under a Settings label, with the extension's sentence and recovery hint passed through unchanged.**

## Decisions Made

- **Success test:** a bridge result is a success only when `success === true`. Anything else goes to `mapFSBError`, and a null result is rendered as `{ success: false }`.
- **Write preflight branches:**
  - Preflight success with `writable === true`: `mcp:set-setting {key, value}`.
  - Preflight success with any other `writable`, or a preflight failure whose `code` (else `errorCode`) is `SETTING_UNKNOWN_KEY`: `mcp:set-setting {key}`.
  - Any other preflight failure, for example `SETTING_STORAGE_FAILED`, `AGENT_CAP_REACHED` or a non-settings error: rendered with no write sent.
- **Local error sentences:**
  - value without key: `value needs a key. Call settings with key and value.`
  - length: `key must be at most 64 characters.` and `value must be at most 2048 characters.` (the limit only, never the input)
  - unsupported: `This FSB extension does not support settings yet. Update the FSB extension.`

  Each carries the plan's `recoveryHint` for its code.

## Accepted D-18 limit (threat T-66.1-23)

Refusals decided inside the MCP process never reach the extension, so they write no D-18 `automationLogs` line:

- zod rejections (a null, object or array value)
- value without key
- an oversized key or value
- `SETTING_UNSUPPORTED`
- a preflight failure other than `SETTING_UNKNOWN_KEY` (for example `AGENT_CAP_REACHED`, `SETTING_STORAGE_FAILED` or a timeout)
- a bridge that is not connected

This is an accepted limit: none of them reaches `chrome.storage`, so no setting can change unlogged, and the client still gets the typed error. Every refusal that can involve a stored setting reaches the extension and is logged there: unknown key, protected key, invalid value, provider not ready, delegated write. V5 must not report these local refusals as a gap. This is a separate id from T-66.1-06, the mitigated silent-recording-disable threat that plan 66.1-05 owns.
