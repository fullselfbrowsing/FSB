<objective>
Keep an open Control Panel in step with settings written from outside it (the MCP settings tool), so a later Save never silently reverts them.

Purpose: SET-02 says the panel, autopilot and run_task share one value per setting. saveSettings writes every field (options.js ~2380), so without this an MCP write is undone by the next unrelated Save (D-16, RESEARCH Pattern 7). The correctness guarantee is the Save-time filter; the in-place refresh (simple fields and the provider group) makes the open panel show the MCP-written value, which the D-01 SC3 V5 check looks at.
Wave note: this plan has no code dependency on 66.1-02 or 66.1-03; it runs after them (wave 4) only because all 66.1 plans share one working tree (`use_worktrees: false`), and its options.js sweep runs most of the suite, which a sibling's build or half-finished edit would disturb.
Output: a `FSBSettingsSync` IIFE in the tail of `extension/ui/options.js`, three small wiring edits in that file, and `tests/settings-panel-sync.test.js` registered in the root chain.

- `keyForElementId(id)`: the schema key for a control id: the id itself when it is a schema key; aliases for coupled controls (maxIterationsSlider -> maxIterations, the maxDOMElements slider/stepper ids -> maxDOMElements, the elementCacheSize preset and custom ids -> elementCacheSize, the agent-cap input/reset ids -> fsbAgentCap, autoAnalyzeToggle -> autoAnalyzeMemories; confirm every id in control_panel.html); modelProvider and modelName -> the provider group; otherwise null.

- Internal `lastKnown` map (schema key -> last known stored value): replaced by `reset(snapshot)`, and updated with every schema key's `newValue` that noteStorageChanges sees (self-writes and external changes alike).
- `noteSelfWrite(obj)`: remembers a key/value the panel itself is about to write ONLY when the key is absent from `lastKnown` or its value is not JSON-equal to `lastKnown[key]` (an unchanged value produces no onChanged echo, so recording it would leave a stale record that could later swallow a real external change back to that value).
- `noteStorageChanges(changes, area)`: ignores area !== 'local' and non-schema keys; updates `lastKnown`; for each schema key whose newValue JSON-equals a remembered self-write, consumes that self-write and skips it; otherwise marks the key externally changed (pending). Returns `{ apply: { key: newValue } }` for pending keys that are untouched, writable and have an in-place refresh mapping. The four provider-group keys are writable and DO appear in `apply` when changed, provided none of the four is touched (touching any marks all four).
- `filterForSave(settings)`: deletes from `settings` every pending key that is not touched; returns the array of dropped keys.
- `noteSaved(writtenKeys)`: clears the touched set; removes the written keys from pending (dropped keys stay pending until the next load). Self-write records are not cleared here, because a record exists only for a key that will produce an echo.
- `reset(snapshot)`: clears touched, pending and self-writes and sets `lastKnown` to the schema keys of `snapshot` (an object; a non-object means {}); called when loadSettings takes its storage snapshot.
- `applyToForm(apply, deps?)`: updates the visible controls for each key using the same statements loadSettings uses (value/slider/display triplets, refreshStepper, setAgentCapControlValue, captcha/login visibility helpers, sttProvider checkbox = value === 'whisper', voiceInputEnabled checkbox together with `persistedVoiceInputEnabled`, autoAnalyzeToggle checkbox).
