# Plan 59-02 — Wake-Safe Scheduling, Revalidation, and Local Delivery

## Objective

Add an injected alert runtime and the trusted background adapters that derive current candidates, reconcile Chrome alarms, revalidate every authority before effect, create one native local notification, and route current evidence clicks safely.

## Task 1 — Controlled RED runtime/background contracts

Create `tests/skopeo-alert-runtime.test.js` and extend `tests/skopeo-hud-runtime.test.js` with exact source-extracted background seams. Cover missing/orphan/correct alarms, concurrent reconcile, same-day delay, next-day miss, startup recovery, attempted interruption, notification failure/denial/unavailability, duplicate alarm events, account/corpus/access/revision/lineage/deadline/owner/citation drift, supersession order, and stale notification clicks.

**Gate:** controlled RED marker and source absence contract pass.

## Task 2 — Implement alert runtime and Chrome permission/effect boundary

Create `extension/utils/skopeo-alert-runtime.js`. Modify:

- `extension/manifest.json` to add only `notifications`;
- `extension/background.js` import/order and private runtime construction;
- manifest/permission regression tests as required by existing validation.

The runtime accepts injected store/engine/alarms/notifications/revalidator/clock/timezone/runtime URL dependencies. Durable state is truth; alarms use exact `skopeoAlert:` opaque names. Persist attempted before `notifications.create`, delivered after promise success, failed on closed errors, missed after the alert civil date, and superseded before clearing/replacing an alarm. Basic notification copy is built from the revalidated candidate only.

**Gate:** alert runtime tests, manifest validation, and `node --check` green.

## Task 3 — Wire current candidate/revalidation and synchronous lifecycle events

Modify `extension/background.js` to:

- derive one current alert candidate from exact graph/truth/corpus proof;
- reconcile after current truth refresh/publication and trusted boot;
- route prefixed alarms before unrelated branches in the existing single listener;
- call one deduplicated reconcile from `onInstalled` and `onStartup` without resetting correct alarm times;
- synchronously register notification click/button handlers and freshly authorize governing evidence before navigation;
- expose no generic message, URL, or store facade.

Extend runtime/truth/corpus/storage tests for real production join behavior. Revalidator returns a complete current candidate or closed disposition, never a caller-trusted boolean.

**Gate:** alert runtime/HUD/truth/corpus tests, storage boundary, `npm run validate:extension`, and focused existing truth/HUD regressions green.

## Must-Haves

- Alarm firing is not delivery proof and cross-day delay never sends retroactively.
- Duplicate reconcile/alarm events create at most one notification effect.
- Every delivery and click has fresh full authority; stored copy/URL is never enough.
- Notification content has vendor, deadline, consequence, owner, and governing evidence label with no private fields.
- API unavailability/failure records failed and has no fallback delivery channel.
