<objective>
Extend the bench's single row contract (scripts/bench/lib/runs.mjs) for the three-arm comparison: a run-condition dimension in the seeded ABBA schedule, the `condition_not_applied` infra code and the `jev_measurement_missing` flag (set by 71-03 only when a switched-on run's fast_mode summary reports Jev attempts but its jevMeasurement never arrived), and an additive, versioned v2 run row with `condition`, `jev`, `safety`, `endLabel` and `fastMode` blocks, while schema-1 rows (the V1 baseline) validate unchanged. The `fastMode` block is the D-09 item-3 substitution recorded in 71-SYNC-RECHECK S8: Phase 70 keeps `status` unchanged and puts the typed outcome in `runTask.fastMode`, and 70-07 left the committed-row projection to Phase 71. The `jev` block implements the 71-SYNC-RECHECK Exposure rule: a switched-on run with no Jev attempt has known zero exposure (acted false), never unknown exposure (2026-10-16 orchestrator decision).

Purpose: SC1-a needs the baseline, control and fast runs on one corpus with rows the evaluator can trust; SC1-b/SC2 need exposure, cost and safety evidence per run (D-04, D-08).
Output: runs.mjs v2 contract, two new registered suites, two fixtures, the moved infra/flag pins.
