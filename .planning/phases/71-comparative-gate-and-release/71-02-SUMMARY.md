## The Exposure rule as implemented

`jevBlock` takes the first case that applies:
1. **`raw.jevMeasurement` is a plain object:** `'measurement'`.
   - Counts are sums over `commands[]`, and a total is null when no command reports the number.
   - `acted = fastSteps > 0`.
   - `calibrationStatuses` counts acted attempts only (`fallback === null && op !== null && stepOutcome !== null`, where a missing key counts as null).
   - `fallbacks` counts non-null fallbacks. Unknown values map to `other` in both maps.
   - `servedModels` and `instrumentVersions` are the sorted, distinct `safeString(…,128)` values from `jevCalled` attempts, at most 10 each.
   - `attemptsTruncated = attempts.length >= 100`.
2. **Else, the projected `runTask.fastMode.jev` summary is non-null:** `'summary'`.
   - `acted = fast_steps > 0`.
   - When acted, `calibrationStatuses = {<calibration or other>: 1}`; otherwise `{}`.
   - `fallbacks`, the model lists and `attemptsTruncated` are null.
3. **Else, a counted autopilot `on` row with no plain-object `runTask.fastMode`:** `'no_block'`, with `acted false` and counts 0. Two more conditions apply:
   - `raw.flags` is an array that does not include `session_detail_missing`;
   - the row's `infraError` is null.

   The comment cites 68-05-PLAN.md:26, 70-05-PLAN.md:107 and `sessionDetailFlags`.
4. **Otherwise:** `source null`, and every jev field is null. `usd` is `{provider:null, estimate:null}`.

- **No S4 drift substitution.** 71-SYNC-RECHECK S4 recorded "persistence order: same save", so case (3) yields `'no_block'`.
- **"exposure cross-check" test.** It covers every case in the plan, including the counted timed-out row:
  - flagged `session_detail_missing`, it gives `acted null, source null`;
  - with flags `[]`, it gives `'no_block'`.

## computeSafety

Inputs are `{task, requests, dropped}`. The two outputs:
- **`requestOvercount`:** the largest `max(0, matched - count)` over the request checks without `jsonEquals`. `matched` follows outcome.mjs `checkRequest`: the method is compared case-insensitively and the path exactly.
- **`unexpectedMutations`:** requests under `/api/` whose method is not GET, HEAD or OPTIONS and whose (method, path) pair no request check names.

The result is null (unverifiable, never 0) in these cases:
- the log is not an array;
- `dropped > 0`;
- `dropped` is not a non-negative safe integer (undefined and null mean unknown);
- the dropped count is unknown and the log has at least `MAX_REQUESTS_PER_RUN` (2000) entries;
- the task has no `success.all`.

What the suite proves for all 12 core tasks:
- an exact log gives `{0,0}`;
- a duplicated total-count request gives overcount 1;
- an extra unnamed `/api` POST gives 1 mutation;
- a DELETE on a path that only a POST check names counts as a mutation.

A source pin ties `MAX_REQUESTS_PER_RUN` to `maxRequestsPerRun: 2000` in `fixture-server.mjs`.

## Decisions Made

- **The validator mirrors the producer's invariants** (producer/validator parity, gotcha 6). Beyond the plan's rejection list it also refuses:
  - `jev_unrecorded_not_null`: a null source with any non-null jev field;
  - `jev_no_block_invalid`: `no_block` on a row that is not a counted autopilot `on` row, or with non-zero counts;
  - `safety_infra_not_null`: an infra row whose safety block is not all null;
  - a non-boolean `claimedSuccessOnFail` on a counted row.

  Every row the producer can emit passes these rules (tested).
- **Errors name rules and paths, never values.** A count-map key outside the vocabulary gives `vocabulary:<path>`, never the key itself.
- **Deterministic count maps.** Keys appear in vocabulary order, with `other` last.
- **`FAST_MODE_ROW_SOURCES` and `FAST_MODE_ROW_OUTCOMES` are exported** so the parity test checks the real mapping table instead of a copy.
