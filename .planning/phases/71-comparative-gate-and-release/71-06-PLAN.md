The 71-01 rules apply. evaluate.mjs is pure: no clock, environment, filesystem, git or network; header comment copied from the stats.mjs contract (same input and seed give the same result).

Inputs (built by the CLI in 71-07, by synthetic.mjs in tests):
`evaluateGate({ gate, gateSha256, baseline:{identity, runs, safety}, autopilot:{identity, runs}, claude:{identity, runs}, suites:{ran, results:[{command, exitCode}]}, fallback = null }, { iterations } = {})` where `baseline.safety` is a Map runId → {requestOvercount, unexpectedMutations} from the baseline sidecar (71-07) or null, `fallback` is null or `{pin:{identity, runs, safety}, candidate:{identity, runs}}` (the core-rebaseline-71 campaigns; pin.safety is that campaign's sidecar Map or null), and `iterations` defaults to gate.bootstrap.iterations (tests pass a small number; the CLI never overrides it).

Output: `{ refusals:[{code, detail}], campaigns:{baseline, autopilot, claude: {id, createdAt, gitSha, rounds, meetsMinRounds, resumeDrift}}, exercise:{status:'exercised'|'not_exercised', reasons, onCounted, actedRuns, actedShare, pairs, uncalibratedActedRuns, leakRuns}, sentinel:{status:'pass'|'trip'|'inconclusive', reasons, completion:{diff, ci}, speed:{estimate, ci}, blocker}, paths:{'jev-mcp-run-task', 'jev-autopilot', 'mcp-non-jev': {label, verdict:'pass'|'fail'|'inconclusive'|'not_exercised', reasons, faster?, source ('primary'|'fallback', non-Jev only), criteria:{...}}}, fallback:{status:'not_supplied'|'not_triggered'|'used'|'refused', primaryVerdict, primaryReasons, verdict, reasons, refusals, campaigns:{pin, candidate}}, categories, sensitivity, inputs:{iterations, seed} }`. When refusals is non-empty, paths may be omitted.

Rules (gate = scripts/bench/gate/release-gate-v1.0.0.json; read numbers from the gate object, never hard-code them):
- Counted = infraError === null; completed = counted and pass. Groups: baseline autopilot rows, baseline claude rows, autopilot off, autopilot on, claude off.
- speedComparison(controlRows, treatmentRows, {iterations, seed, level}): tasks = task ids present in both; {id, a: completed control wallMs, b: completed treatment wallMs} (finite numbers only); geoMeanMedianRatio(tasks, ...). Only `wallMs` is ever read for speed.
- aaFloor: aaNoiseFloor over completed control-condition rows per task ({round, wallMs}), same iterations and seed; status n/a → speed criterion inconclusive.
- completionComparison(controlRows, treatmentRows, z): x/n over counted rows; newcombeDifference(xT, nT, xC, nC, z) (treatment minus control).
- Safety events for a row: requestOvercount > 0, unexpectedMutations > 0, and claimedSuccessOnFail recomputed as (isClaimedSuccess(row.arm, row.claimed, words) OR, for candidate autopilot rows only, row.fastMode !== null and gate.claimWords.autopilot.candidateTypedOutcome includes row.fastMode.outcome) AND row.pass !== true, with words = gate.claimWords.autopilot.baseline for baseline rows and .candidate for candidate rows. The row's own flag is descriptive. The union is per run (one claimedSuccessOnFail event at most), so a typed done that agrees with a success status adds nothing, and a typed done with a non-success status still counts (false done, M-70-04). For schema-1 baseline rows the two evidence numbers come from baseline.safety; a missing entry is unverifiable.
- Exposure for safety (gate.safety.unknownExposure 'acted', applied only to rows still unknown): a counted 'on' row is acted for rule (a) when jev.acted is true, or when jev.acted is null (unknown exposure: jev.source null after the 71-02 Exposure rule); it is non-acted for rule (b) only when jev.acted === false, which includes every row with no Jev attempt (jev.source 'no_block', or 'summary' with zero fast steps). The evaluator reads exposure only from jev.acted and jev.source as 71-02 produced them, and never re-derives it from flags. A no-block 'on' row whose session detail was never read already carries jev.source null from 71-02, so it takes the unknown reading. A 'no_block' row never does.
- Jev safety: rule (a) any event in an acted 'on' row → fail 'acted_safety_event'; rule (b) events per counted run in non-acted 'on' rows greater than in 'off' rows → fail 'excess_llm_path_events'; any counted on/off row with null evidence → inconclusive 'safety_unverifiable' (unless fail); suites.ran false → inconclusive 'suites_not_run'; any suite exitCode !== 0 → fail 'tighten_only_suite_failed'.
- Non-Jev safety: events per counted run in claude candidate rows greater than in baseline claude rows → fail; baseline evidence unverifiable → inconclusive.
- Exercise (autopilot campaign): acted share = 'on' counted rows with jev.acted === true (null never counts here) / 'on' counted rows, must be >= exercise.minActedShare; any acted row whose calibrationStatuses has a key other than 'calibrated' → not exercised; servedModels union and instrumentVersions union over 'on' rows must each have exactly one value (null lists, from 'summary' rows, contribute nothing); any counted 'off' row with jev.source !== null ('measurement' or 'summary', whatever its acted or jevCalls values; for example a jevMeasurement holding only a local sensitive_goal attempt with jevCalled false) → condition leak → not exercised with reason 'condition_leak' (gate exercise.noOffActivity; D-16 amendment, 2026-10-16: 68 D-01 makes the off path equal the pin, so an 'off' run has no Jev attempt at all). The capture-arm condition holds by construction (an armed capture makes the run condition_not_applied) and is reported as such.
- Jev verdict precedence: safety fail → not_exercised → inconclusive (autopilot campaign under minRounds, resume drift, A/A floor n/a, safety inconclusive) → fail (speed or completion) → pass. Both Jev paths share every number; they differ only in label.
- Non-Jev verdict precedence: safety fail → inconclusive (identity mismatch on identityMatch.claude, baseline or claude campaign under minRounds, resume drift, corpus digest mismatch, sentinel not 'pass', baseline safety unverifiable) → fail (speed: CI upper > nonJevSpeed.ciUpperAtMost; completion) → pass; `faster` = CI upper < nonJevSpeed.fasterCiUpperBelow.
- Sentinel: baseline autopilot rows vs autopilot 'off' rows: identity mismatch on identityMatch.autopilot or under-round → inconclusive; completion CI not inside (−margin, +margin) or speed CI not inside speedBand → trip; else pass. A trip carries gate.sentinel.blocker.
- Identity fields: dotted paths; 'corpus' compares corpusDigest(identity.tasks) with gate.corpusLockSha256; 'chromeMajor' parses /Chrome\/(\d+)/ from identity.chrome.browser. A missing value on either side is a mismatch. identityMatch.reported fields are copied into the result, never compared.
- Resume drift (Pitfall 8): any identity.resumes[] entry whose claudeVersion differs from hosts.claude.version (when present) or whose chromeBrowser major differs.
- Refusals: autopilot or claude identity.gate missing or its sha256 !== gateSha256; identity.campaignId !== the gate's id for its role; candidate git.dirty !== false; autopilot and claude git.sha differ; baseline git.sha does not start with '8a058bdf'; a campaign's schedule (arms, seed, conditions) differs from the gate; a candidate row with schemaVersion !== 2.
- minRounds: identity.schedule.rounds >= minRounds and the highest observed row.round >= minRounds.
- Sensitivity (non-decisive): the same comparisons at level gate.bootstrap.sensitivityLevel (0.975) and z = 2.241402727604947.
- Fallback (gate.fallback): when `fallback` is null, result.fallback.status is 'not_supplied'. When supplied: refusals inside result.fallback.refusals (never the top-level list): campaign ids, seeds, conditions or row schemas differ from gate.fallback.campaigns → 'fallback_campaign_mismatch'; pin git.sha does not start with '8a058bdf' → 'fallback_pin_not_pin'; candidate git.sha differs from the primary candidates' git.sha, or its gate sha256 differs from gateSha256 → 'fallback_candidate_not_measured'. If the primary non-Jev verdict is not 'inconclusive' or none of its reasons starts with a gate.fallback.triggers entry → status 'not_triggered' and nothing changes. Otherwise the non-Jev rules run unchanged on (pin as baseline, candidate as candidate) with identityMatch.claude compared between the two, minRounds from gate.fallback.campaigns, the pin sidecar for baseline safety and no sentinel (gate.fallback.sentinel 'not_applicable'); status 'used'; the result replaces paths['mcp-non-jev'] (verdict, reasons, criteria, faster) with source 'fallback' and records primaryVerdict and primaryReasons. A refused fallback leaves the primary verdict in place with status 'refused'.
- Categories (descriptive): per row.category ('mixed', 'click-heavy') the Jev and non-Jev speed ratios with CIs; targets from gate.targets reported met when the CI upper bound <= 1 / lower target (autopilotMixed on 'jev-autopilot' mixed; mcpClickHeavy on 'jev-mcp-run-task' and 'mcp-non-jev' click-heavy; mcpUatStyle 'not measured: no UAT-style tasks in the core set').
