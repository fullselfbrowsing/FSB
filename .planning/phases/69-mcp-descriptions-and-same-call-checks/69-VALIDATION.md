## Sampling Rate

- **After every task commit:**
  - Run the task's `<automated>` command.
  - Run the pin suites for every file the task edits (table below; RESEARCH Findings 4–7 and CONTEXT D-24).
  - For edits to `extension/ws/mcp-tool-dispatcher.js` (38 referencing tests) and `extension/ws/mcp-bridge-client.js` (28), also run the regression sweep against the Wave 0 baseline.
  - For any `mcp-bridge-client.js` edit, scan the output of `action-tool-agent-scoped` and `ownership-error-codes` for "skipped". Those guards pass silently when `resolveAgentTabOrError` leaves the 4,500-character window (RESEARCH Finding 5).
- **After every plan wave:**
  - Run every new Phase 69 suite present so far.
  - Run the four registry hash pins: `tool-definitions-parity`, `capability-mcp-surface`, `capability-autopilot-parity` and `recipe-schema-lock`.
  - Run `mcp-version-parity`, `delegation-phase-contract`, `npm run test:mcp-smoke:tools`, `npm run test:screenshot` and the regression sweep over every file edited in the wave.
  - Run each new suite once more under `npx --offline -y node@20`.
- **Before `/gsd:verify-work` (phase gate):**
  - `npm run validate:extension && npm test` is green (run in the background and waited for; it can exceed the 10-minute foreground limit).
  - `npm run test:mcp-smoke:tools` and `npm run test:screenshot` are green.
  - `node scripts/mcp/tools-list-baseline.mjs --check` passes locally, where git history is available.
  - The footprint audit (row `ALL-b`) is clean.
  - Every new suite passes under Node 20.
  - The three showcase crawler files are restored.
  - A red `EADDRINUSE` in the chain means the chain stopped early and later suites never ran. Since the 2026-10-12 main merge, the whole chain passes with the native-host hub on 7225, so a red port-bound suite is a real failure.
- **Max feedback latency:** 60 seconds per task check. The slow suites (`npm run test:screenshot`, `npm run test:mcp-smoke:tools`, the four registry hash pins and similar) do not go in a task's `<automated>` command when they would push it over 60 s. They run once in the plan's wave gate in `<verification>` (69-02 and 69-06 do this), and the SUMMARY records each exit. Measured on 2026-10-15 (plan-checker round 2): `npm --prefix mcp run build` takes about 2.2 s (a clean build), `npm run test:screenshot` about 2.7 s and `npm run test:mcp-smoke:tools` about 2.4 s, each including its own rebuild. 69-04 Task 1's whole `<automated>` chain, with both scripts and their two extra rebuilds, takes about 9.4 s. So the per-task uses in 69-04 (T1-T3) and 69-07 (T1) stay well inside the 60 s budget and are kept for earlier feedback on registration-site edits.
