Persisted records use only JSON-safe `{tabId, generation, status, terminalGeneration, updatedAt, reason}` fields. `beginGeneration` is the only operation that creates a newer generation. `markActive` may retain only the exact controller marker `prepared-awaiting-commit` (or null), and `clearActiveReason` removes that marker only for the matching ACTIVE generation after ready. `beginTermination` records `terminalGeneration` before cleanup, and both STARTING and ACTIVE accept only an exact generation match. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Asynchronous work to session reducer | Promise/timer/message completion is untrusted with respect to the current generation. |
| Tab-scoped caller to persisted record | A caller-provided tab or generation must not select another tab's state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-01 | Tampering | `acceptsGeneration`, `beginTermination`, `finishTermination` | mitigate (blocking) | Record the terminal generation before cleanup, reject all work in TERMINATING/OFF, and prove kill-plus-reinvoke with a real deferred completion. |
| T-52-05 | Denial of service | reducer event replay | mitigate | Make READY/TERMINATE/FINISH idempotent and preserve a single monotonic record per explicit tab ID. |
| T-52-07 | Spoofing | tab record selection | mitigate | Require a positive explicit tab ID and reject cross-tab state/event combinations in both reducer and tests. |
</threat_model>
