<interfaces>
Use these exact page/service-worker message envelopes:

```javascript
// inbound, accepted only from chrome.runtime and with a positive generation
{ action: 'skopeo:prepare', generation }
{ action: 'skopeo:commit', generation }
{ action: 'skopeo:probe', generation }
{ action: 'skopeo:terminate', generation, reason }

// outbound; tab identity is derived by the service worker from sender.tab.id
{ action: 'skopeo:prepared', generation, placement: 'full'|'compact' }
{ action: 'skopeo:ready', generation, attention: 'ambient' }
{ action: 'skopeo:kill-request', generation, reason: 'close'|'escape'|'unsafe-layout'|'navigation' }
{ action: 'skopeo:teardown-complete', generation, reason, resources }

// synchronous probe responses; a delivery failure is normalized by the worker to the missing shape
{ success: true, generation, status: 'active', attention: 'ambient', mounted: true }
{ success: false, generation, status: 'stale', code: 'SKOPEO_STALE_GENERATION' }
{ success: false, generation, status: 'missing', code: 'SKOPEO_RUNTIME_MISSING' }
```

Install one document sentinel:

```javascript
window.__FSB_SKOPEO_RUNTIME__ = {
  prepare(envelope) {},
  commit(envelope) {},
  probe(envelope) {},
  terminate(envelope) {},
  getSnapshot() {},
  activateControlledFixtureForTest() {},
  disposeForReplacement() {}
};
```

Script evaluation installs the listener/sentinel only. It does not insert a host or invoke `prepare`/`commit`. `prepare` may create detached shell state and an opaque prepared placement but must leave root, popover-top-layer, active-keyboard-listener, focus, and attention snapshots unchanged at zero/Ambient. Only an exact matching `commit` after the worker has accepted `skopeo:prepared` may call `mountAmbient`. `probe` is read-only and returns the typed active/stale shape without mounting, rendering, focusing, or changing attention; absence of a listener is normalized by Plan 04 to the typed missing shape. `activateControlledFixtureForTest` returns false unless the extension isolated world has the explicit `window.__FSB_SKOPEO_TEST_FIXTURE__ === true` flag and a committed active generation; no runtime message or ordinary UI action can set the flag or call the hook.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Service-worker message to document runtime | Messages can be delayed, duplicated, reordered, or delivered after a generation ended. |
| Runtime callback to shell | Async callbacks must not render after abort/teardown. |
| Document keyboard/page lifecycle to Skopeo | Host events are unrelated unless a visible Skopeo state consumes them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-52-01 | Tampering | prepare/commit/probe/render/teardown callbacks | mitigate (blocking) | Exact generation plus AbortSignal checks immediately before every side effect; prepare remains root-free, commit requires the worker-accepted generation, probe is read-only, and terminal-before-abort-before-destroy order is tested with released deferred work. |
| T-52-02 | Denial of service | runtime event handling and dormant listeners | mitigate (blocking) | Register key/page handlers only after commit, suppress only shell-consumed events, and remove runtime/key/page listeners plus sentinel/fixture ownership on every terminal path; unsafe/failed start remains root-free. |
| T-52-03 | Elevation of privilege | inbound fixture/render messages | mitigate (blocking) | Fixed action allowlist, typed generation envelope, no generic HTML/render action, and no ordinary-message fixture entry. |
| T-52-04 | Denial of service | Escape/focus teardown | mitigate | Delegate focus restoration to the shell and ignore composing/repeated/unrelated keyboard input. |
| T-52-05 | Denial of service | sentinel/listener replacement | mitigate | Dispose prior sentinel, hold/remove exact listener identities, prove zero listener/sentinel residue while off, and make duplicate prepare/commit/teardown plus later reinjection idempotent. |
</threat_model>
