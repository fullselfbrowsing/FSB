## Accomplishments

- Added strict dual-runtime canonical schema authority that rejects non-JSON values, sparse/accessor arrays and objects, cycles, non-plain prototypes, and non-finite numbers, then hashes the exact UTF-8 canonical bytes with native SHA-256.
- Exposed pure `getResolvedParamsSchema` and `validateResolvedArgs` router helpers and made internal invoke use the same implementation, preserving all existing typed error behavior and producing zero handler calls during inspection.
- Exported the installed catalog resolver and regenerated schema-v2 authority from resolved T1a handlers with no `https://${service}` execution fallback.
- Separated each profile's `service`, `serviceOrigin`, and 166 collision-free `admittedPageOrigins` entries from each capability's installed `executionOrigin`; an origin mismatch remains visible but static and non-invocable.
- Kept complete canonical parameter schemas background-side and projected only `executionOrigin`, `schemaDigest`, and an honest summary capped at 12 displayed names while retaining the full property count.
- Replaced generator-derived coverage expectations with an independent resolver-backed verifier: 2,314 descriptors, 128 profiles, 1,285 source-Ready rows, 1,279 comparable rows, and zero tier/origin/class/schema mismatches or origin collisions.

## Decisions Made

- Normalize authority only from installed resolved T1a entries with a closed handler/descriptor side-effect classification, exact HTTPS handler origin, and the router's complete schema. Missing authority makes a row non-executable; it never falls back to a canonical service URL.
- Assign same-app origin collisions to the profile whose canonical service origin owns that origin, allowing Notion and Slack pages to share their app-stem capability set without creating profile ambiguity. Keep the multi-stem Atlassian origin explicitly ambiguous and fail quiet.
- Bind catalog/profile versions to full descriptors and execution authority, including complete canonical schema bytes and digests, so a stale digest paired with a mutated schema cannot replay.
- Preserve full parameter counts even when only 12 required/optional names are displayed. The `truncated` bit is derived from omitted names, and neither the summary nor schema titles/target-like fields can authorize execution.
- Keep the native runtime digest asynchronous and expose digest injection only through a clearly test-only seam; generation uses Node's built-in SHA-256 over the same exported canonical string and adds no dependency.
