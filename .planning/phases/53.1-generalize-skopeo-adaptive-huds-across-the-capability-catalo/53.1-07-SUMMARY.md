## Decisions Made

- Dynamic content order is schema, context router, app-context resolver, anchor registry, adapter registry, adaptive composer, renderer registry, shell, then runtime. The projection is created from a fresh exact tab URL and sent once before the existing prepare/commit sequence.
- A ready-read request must match the current tab/generation/origin/catalog/profile/context/entity tuple, select a current-service canonical `t1-ready` read descriptor, validate its args, and consume its action token before exactly one existing-router call. The same tuple must still be live after await.
- Same-document navigation accepts only an enriched exact higher-context-epoch authority envelope; the legacy boolean route fallback was removed because it could not prove the replacement tuple.
- All controller gates and action tokens are invalidated on replacement or kill. The content runtime withdraws dependent state before higher-epoch route replacement and aborts work before disposing the same eleven owned resource categories.
- Catalog closure distinguishes 130 exact `(appStem, service)` pairs from 129 distinct services: 128 services resolve to one stem and the Atlassian-shared service is intentionally ambiguous and fail-closed.
