<interfaces>
`extension/catalog/skopeo-consequence-targets.js` is a dual-export frozen data module:

```text
FsbSkopeoConsequenceTargets = {
  schemaVersion: 1,
  contracts: {
    SLUG: {
      effectLabel: TRUSTED_BOUNDED_TEXT,
      progressLabel: TRUSTED_BOUNDED_TEXT,
      targetRoles: [{ field, label, render, maxLength }],
      materialRoles: [{ field, label, render, maxLength }],
      excludedFromCollection: [REVIEWED_FIELD_NAME]
    }
  },
  getContract(slug) -> frozen contract | null
}
```

`render` is exactly `scalar` or `bounded-object`. `maxLength` is a reviewed per-role input/render limit; for current string fields it is at most 256 so an accepted value can be shown completely rather than silently truncated. `excludedFromCollection` is exact reviewed metadata, not a schema inference; it is empty for all six safe Notion optional fields below. The five initial contracts are:

| Slug | Effect | Target roles | Material roles |
|------|--------|--------------|----------------|
| `slack.chat.postMessage` | Send one message | `channel` / Slack channel | `text` / Message |
| `notion.create_page` | Create one page | `title` / New page title; optional `parent_page_id` / Parent page ID | `title` / Page title; optional `icon` / Page icon; optional `content` / Page content |
| `notion.update_page` | Update one page | `page_id` / Page ID | `page_id` / Updated page ID; optional `title` / New title; optional `icon` / Page icon; optional `cover` / Page cover |
| `notion.create_database` | Create one database | `parent_page_id` / Parent page ID | `title` / Database title |
| `notion.create_database_item` | Create one database item | `database_id` / Database ID | `title` / Item title |

The generated background capability adds:

```text
consequenceContract: COMPILED_FULL_FROZEN_CONTRACT_OR_NULL
consequenceDigest: "sha256:..." | null
consequenceCompatible: true | false
acceptedConsequenceFields: SORTED_EFFECTIVE_COLLECTOR_FIELD_NAMES
excludedConsequenceFields: SORTED_REVIEWED_EXCLUSIONS
```

Content projection receives only `consequenceCompatible` and `consequenceDigest`; it never receives role metadata. The gate obtains the full compiled contract from background through `getCurrentCapabilityAuthority(slug)`.

Compilation computes `effectiveArgumentContract` by applying only reviewed `excludedFromCollection` entries to Plan 09's safe collector. It then requires the sorted union of `targetRoles.field` and `materialRoles.field` to equal every field in that effective collector; a missing optional role is a compatibility failure, not an ignored parameter. Current Slack/Notion contracts exclude none of their safe scalar fields. Plan 09 already omits Notion's open optional `properties` objects, and background continues to reject them if forged.

`materializeConsequence(compiledContract,args)` returns exact bounded trusted labels/value text plus `renderedFields`, the sorted unique field names actually represented in target or material, or null. The gate independently compares `renderedFields` with the sorted own keys of the validated supplied args. It never consults semantic entity/page/schema title/action-label grammar and never permits a supplied accepted field to disappear from confirmation.
