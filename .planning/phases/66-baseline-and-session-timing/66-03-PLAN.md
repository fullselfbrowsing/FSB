SHARED CONTRACT (verbatim; plans 66-04 and 66-06 implement against the same names):
- Symbol: `Symbol.for('fsb.mcp.call-timing')`. The bridge client's top-level identifier is `MCP_BRIDGE_CALL_TIMING`. The dispatcher (plan 66-06) uses a DIFFERENT identifier, `MCP_DISPATCHER_CALL_TIMING`, because both files share one classic-script global lexical scope, and a duplicate top-level `const` throws on the second importScripts.
- Ingress stamp value: `{ receivedAt: <Date.now() ms> }`, defined with `Object.defineProperty(payload, MCP_BRIDGE_CALL_TIMING, { value, enumerable: false, configurable: true })`.
- Recorder entry field: `timing: { v: 1, receivedAt, completedAt, fsbMs }`. completedAt is `Date.now()` taken synchronously at the recording call site, before any fire-and-forget enqueue; `fsbMs = completedAt - receivedAt`. When there is no stamp, the field is null or omitted, never 0.
- Validation used by the recorder, journal and Sheets redaction: v === 1; receivedAt and completedAt are safe non-negative integers; completedAt >= receivedAt; fsbMs is recomputed as completedAt - receivedAt. Anything else is dropped.
- Journal: `metadata.timing` has the same shape and is present only when valid.
- Legacy MCP actionHistory row: adds `timing` (same shape) and `durationMs = timing.fsbMs`, only when timing is valid. Plan 66-04 makes automation-logger persist both.
- fsb://config payload (the `_handleGetConfig` return): `{ config: { providerKind, modelProvider, modelName, maxIterations?, domOptimization?, maxDOMElements? }, extension: { id, version, measurement: { callTiming: 1, sessionDetailJournal: 1 } } }`.
- Use `Date.now()` only. `performance` is undefined in the vm harnesses.
