BASIS LABELS (verbatim contract; W1, orchestrator decision 9 D-02/D-10 reconciliation):
- The legacy `totalCost` is always a price-table sum, so `'provider'` never applies to it. Its basis depends on whether the session has a `measurementSummary` (I-B):
  - With a summary: `'unavailable'` when `measurementSummary.costSource === 'unavailable'` or any stored iterationTiming row has `pricingKey === null`, because the legacy total then includes the unknown-model display fallback rather than a real price-table estimate. Otherwise `'estimate'`, even when the total is 0 (for example a local lmstudio run).
  - Without a summary (pre-Phase-66 sessions): `'estimate'` when totalCost is finite and > 0, else `'unavailable'`.
- The legacy token totals sum provider-reported usage. Their basis is `'provider'` when either total is > 0, and `'unavailable'` otherwise.
- `measurement.legacyTotals.costBasis` and `measurement.legacyTotals.usageBasis` carry these two bases.
- Every get_session_detail session object that contains a `totalCost` key gains `totalCostBasis` beside it. Every list_sessions entry that contains a `totalCost` key gains `totalCostBasis` too.
- Stored value (I-2): sessions saved since plan 66-04 carry `totalCostBasis`, computed by this same cost rule at save time (`computeLegacyCostBasis` in automation-logger.js), on both the session record and its fsbSessionIndex entry. Index entries never carry measurementSummary or iterationTiming, so the rule cannot be recomputed from a list entry. Both routes therefore use a stored 'estimate' or 'unavailable' value as is, and compute the rule only when none is stored (pre-Phase-66 sessions, which have no summary). A stored value outside those two is ignored and recomputed. list_sessions and get_session_detail therefore agree for every session.
- The token totals never appear bare over MCP, because the /token/i filter removes them from the generic output; they appear only inside `legacyTotals`, where `usageBasis` labels them.
- The fields are additive and optional (INV-01 / MCP-04 allow optional response fields). No existing field changes value.
