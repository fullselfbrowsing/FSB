FIXTURE PAGE CONVENTIONS (verbatim; every page below follows them):
- Served at `/r/<token>/fixtures/<slug>/<file>`. Every link, script and fetch is RELATIVE. The app API path from a page in `<slug>/` is `../../api/<slug>/<action>`, which resolves to `/r/<token>/api/<slug>/<action>`.
- Shared helper `scripts/bench/fixtures/_shared/bench.js` (loaded as `../_shared/bench.js`, a classic script) defines:
  - `benchPost(action, body)`: POSTs JSON to `../../api/<slug>/<action>`. The slug comes from `document.documentElement.dataset.benchApp`, so every page's `<html>` element carries the literal attribute `data-bench-app="<slug>"`. It resolves with the parsed `{ok}`. Pages call it with a literal action string, for example `benchPost('save', ...)`, which lets the corpus test tie each request check to its page source (W2).
  - `setMarker(name, value)`: finds or creates a visible element with `data-bench-marker="<name>"` and sets its textContent.
  - `setView(params)`: `history.replaceState(null, '', '?' + new URLSearchParams(params))`.
  - At load it sets `document.documentElement.dataset.fixtureReady = 'true'`.
  Every task's `fixtureFiles` lists `_shared/bench.js`.
- Deterministic in-memory state only: no localStorage, sessionStorage, IndexedDB, cookies, Math.random or Date-dependent data. All fixture runs share one origin (127.0.0.1:<port>), so stored state would leak between runs.
- No external resources: no http(s) URLs, CDNs, remote fonts or images. No MutationObserver, setInterval or background fetches. The only network traffic is page and script GETs plus the explicit user-action POST(s).
- JSON request bodies have a fixed key order and sorted arrays, so `jsonEquals` is exact.
- Accessible markup: labels tied to inputs, buttons with visible text, custom widgets with role and aria attributes. Custom (div-based) controls are deliberate on click-heavy tasks.
- Each page shows a small title and instructions-free UI (the task text lives only in the task JSON).
