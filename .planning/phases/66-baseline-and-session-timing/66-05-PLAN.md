TASK SCHEMA (verbatim contract; plan 66-07 writes the corpus against it):
- Core task: exactly these keys: `schemaVersion` (1), `id`, `version`, `set` ('core'), `category` ('mixed'|'click-heavy'), `startPath`, `instruction`, `timeBudgetMs`, `success`, `fixtureFiles`.
- Live task: exactly these keys: `schemaVersion`, `id`, `version`, `set` ('live'), `category` ('reading'), `startUrl`, `instruction`, `timeBudgetMs`, `success`.
- `id`: /^(core|live)-[a-z0-9]+(-[a-z0-9]+)*$/, and its prefix equals `set`. The file is named `<id>.json` under `<tasksRoot>/<set>/`.
- `version`: a positive integer. `timeBudgetMs`: an integer in 30000..900000.
- `instruction`: 20..2000 chars, containing the template token `{startUrl}` exactly once.
- `startPath` (core): starts with `/fixtures/`, ends with `.html`, has no `..`, `//`, `?` or `#`. `fixtureFiles` (core): a non-empty array of relative paths under the fixtures root (no leading `/`, no `..`), and it must include the startPath's file (startPath minus the leading `/fixtures/`).
- `startUrl` (live): an absolute `https://` URL.
- `success`: exactly `{ all: [check, ...] }`, with 1..20 checks.
  - `request` (core only): keys among {kind, method, path, count, jsonEquals}. method is one of GET|POST|PUT|PATCH|DELETE; path starts with `/` and has no `..`; count is an integer in 0..100.
  - `finalUrl`: core uses keys among {kind, pathEquals, queryIncludes} and requires pathEquals; live uses exactly {kind, urlIncludes}.
  - `marker` (core only): exactly {kind, name, equals}; name matches /^[a-z0-9-]{1,40}$/; equals is a string of at most 200 chars.
  - `text` (live only): exactly {kind, includes}, where includes is 1..200 chars.

FIXTURE SERVER CONTRACT (verbatim; plans 66-07 and 66-08 rely on it):
- `startFixtureServer({ root = BENCH_FIXTURES_ROOT, port = 0, secret = <random 32-byte hex>, maxRequestsPerRun = 2000, maxBodyBytes = 65536 })` resolves to `{ port, baseUrl, secret, newRunToken(), runUrl(token, startPath), evidence(token), clear(token), close() }`. The host is always 127.0.0.1 and not configurable.
- Pages: `GET /r/<token>/fixtures/<rel>` serves `<root>/<rel>`. The token matches /^[A-Za-z0-9_-]{8,64}$/; otherwise 404 and not logged.
- App API: any method on `/r/<token>/api/<...>` returns 200 `{"ok":true}` (application/json). The body is parsed by content-type: JSON gives bodyType 'json'; urlencoded gives 'form' (an object); anything else gives 'text'. A body over maxBodyBytes gives 413 and bodyType 'too_large'.
- Every request under a valid `/r/<token>/` is logged as `{t, method, path: stripRunPrefix(pathname, token), query, bodyType, body}`. Static GETs use bodyType 'none'.
- `GET /__bench/evidence?run=<token>` and `DELETE /__bench/evidence?run=<token>` require header `x-bench-secret`, compared in constant time, else 403. The in-process `evidence(token)` returns a deep copy `{requests, dropped}`.
- Every response sends `cache-control: no-store`.

Claude Code task-mode argv to mirror (mcp/src/agent-providers/claude-profile.ts lines ~192-211, read-only): `-p --verbose --output-format stream-json --include-partial-messages --setting-sources "" --disable-slash-commands --no-chrome --strict-mcp-config --mcp-config <path> --agents <serialized fsb agent> --agent fsb --permission-mode dontAsk --tools "" --allowedTools mcp__fsb --disallowedTools Bash,Edit,Write,NotebookEdit,WebFetch,WebSearch --max-turns 40 --no-session-persistence`.
