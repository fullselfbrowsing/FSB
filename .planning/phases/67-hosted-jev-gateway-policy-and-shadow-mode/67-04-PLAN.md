Upstream wire facts (.planning/research/JEV-REFERENCE.md, 67-RESEARCH.md "Pattern 5" and "Pattern 6"):
- Request body exactly `{model, state, questions}`; response `{model, answers, usage:{input_tokens, output_tokens}}`; OpenRouter adds top-level `id`, `provider`, `usage.cost` (USD) and a dated model like `typesafe/jev-1.13-20260917`.
- Choice answer `{type:'choice', choice, confidence, probabilities}`; Noul `{type:'noul', noul}`; probability map order differs from criteria order (look up by key).
- OpenRouter errors `{error:{code:<number>, message, metadata?}}`, and a non-streaming provider failure may arrive as HTTP 200 with only `error`.

Classification table (Pattern 5, within the locked D-16 enum):
| upstream outcome | reason |
|---|---|
| 200 with valid answers | ok |
| 200 with `error` object and no `answers` | classifyStatus(error.code) when numeric, else upstream_error |
| 200 unparseable, over MAX_OK_BODY_BYTES, or answers failing validation | invalid_response |
| 400 or 404 whose slice passes isUnknownModelMessage | unavailable_model |
| other 400, 404, 413, 415, 422, other 4xx | upstream_rejected |
| 401, 403 | auth_error |
| 402 | upstream_billing |
| 408, or the AbortController deadline | timeout |
| 429 | rate_limited |
| 529 | upstream_overloaded |
| 500, 502, 503, other 5xx, any other status, network error, fetchImpl throwing | upstream_error |
isUnknownModelMessage: extract `error.message`, `message` or `detail` from a JSON slice when parseable, else use the raw slice; true when it matches `/\bmodel\b/i` and `/unknown|not (a )?valid|not found|does not exist|retired|deprecated|unavailable|no endpoints/i` (research assumption A1/A2; V2 confirms the real wording, M-67-05).
