This matches the real router: `capability-router.js:806-814` refuses every verdict other than 'allow' when the capability is invoked, returns the RECIPE_CONSENT_* error and audits the call as 'blocked' (consent is granted out of band, never inside the call). - `normalizeGate.paymentFill(result)`: `{approved:true}` -> proceed; `{approved:false, reason}` (timeout, user_declined, sidepanel_unavailable or other) -> deny; malformed -> deny.
- `normalizeGate.permission(result)`: `{denied:true}` -> deny; `{denied:false}` -> proceed; malformed -> deny.
- `normalizeGate.safetyBreakers(result)`: `{shouldStop:true}` -> stop; `{shouldStop:false}` -> proceed; malformed -> stop.
- `normalizeGate.stuck(result)` classifies the real `detectStuck` outputs (`agent-loop.js:455-551`; it never returns null): `{isStuck:false, shouldForceStop:false, reasonCode:null, hint:null}` (not stuck) -> proceed; `{isStuck:true, shouldForceStop:false, reasonCode, hint}` (a hint Jev cannot clear) -> proceed; `{isStuck:true, shouldForceStop:true, ...}` -> stop; anything else (null, undefined, `{}`, a non-boolean isStuck or shouldForceStop, shouldForceStop true with isStuck false) -> stop (fail closed). The JSDoc tells callers that have no stuck result to leave the stuck gate out of combineGates rather than pass null.
- Each normalizer returns `{level, source}` with source 'consent'|'paymentFill'|'permission'|'safetyBreakers'|'stuck'.
- `combineGates(gates)` -> `{level: max level (proceed for an empty array), source:'combined'}`.
- `mergeConfirmation(existingGate, result, options = {})` -> `{level, levelName, existingLevel, jevContribution:'none'|'confirm', requiresConfirmation: level === 1, blocked: level >= 2}`. existingGate is one normalized gate or an array (combined); a malformed existingGate counts as deny. jevContribution is 'confirm' when accept(result,'risk').accepted; or when `options.failClosed === true` and accept(result,'risk') failed for any reason other than 'below_threshold' (Phase 68's code-near-risk hook, D-30); else 'none'. level = max(existingLevel, contribution === 'confirm' ? 1 : 0).
- `toBeforeToolResult(merged)` -> `{shouldStop:false, denied:true, denial:{reason:'jev_requires_confirmation', source:'jev'}}` when merged.jevContribution === 'confirm', else `{shouldStop:false, denied:false}`. It never returns shouldStop true. JSDoc must state that Phase 68 registers its hook AFTER the permission hook and expresses tightening only through `denied` and the confirmation card.
