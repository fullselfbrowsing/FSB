| Boundary | Description |
|----------|-------------|
| operator workstation -> deployed gateway (V2/V3) | The harness and smoke script send labelled requests to production |
| shadow outputs -> committed profile | V3 commits a profile derived from harness output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Information disclosure | run-shadow.mjs, gateway-smoke.mjs | mitigate | Gateway-only (no upstream URL or credential in the scripts); body-free outputs under gitignored .local |
| T-67-09 | Spoofing | harness | mitigate | Refuses on instrumentVersion mismatch or mixed served models; results keyed by served model and INSTRUMENT_HASH; candidate profile only within the pin's family |
| T-67-12 | Tampering | candidate profile | mitigate | Selection only via committed targets.json; seed set provably not_a_fit; profile must pass validateProfile; committing it is a V3 human step |
| T-67-04 | Denial of service | harness against production | mitigate | One request in flight; the gateway's own caps still apply |
</threat_model>
