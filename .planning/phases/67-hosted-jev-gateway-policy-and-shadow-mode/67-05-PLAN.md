ledger.js API (consumed by 67-09 router):
- `recordDecision(db, row, {capUsd = 0} = {})`: row = `{decisionId, createdAtMs, outcome, servedModel, instrumentVersion, calibrationStatus, kinds, elementCount, requestBytes, inputTokens, usageSource, costUsd, costSource, upstreamLatencyMs, gatewayLatencyMs, upstreamStatus, hashKeyPresent}`; one `db.transaction` inserting the ledger row and UPSERTing jev_daily (`INSERT ... ON CONFLICT(day_utc, outcome) DO UPDATE SET requests = requests + 1, ...`). Throws a TypeError and writes nothing for: an outcome outside LEDGER_OUTCOMES; kinds that are not a non-empty array of unique CONTRACT.KINDS members; elementCount or requestBytes that are not non-negative safe integers; a decisionId that is not a string of 1..64 characters; a usage or cost source outside CONTRACT. The router wraps calls in try/catch.
- `LEDGER_OUTCOMES` (frozen): 'ok' plus the upstream-stage reasons 'timeout', 'rate_limited', 'upstream_overloaded', 'auth_error', 'upstream_billing', 'unavailable_model', 'upstream_rejected', 'upstream_error', 'invalid_response', plus 'server_error' (the outcomes of a request that reached the router's upstream attempt; 'server_error' here is a fault after callUpstream, recorded as a row so the attempt's capUsd accrual reaches jev_daily, 67-09). `AGGREGATE_ONLY_OUTCOMES` (frozen): 'disabled', 'not_configured', 'invalid_request', 'payload_too_large', 'sensitive_goal', 'busy', 'spend_cap_reached', 'server_error' ('server_error' here is a fault before any upstream attempt, when nothing was spent). The two lists share exactly one member, 'server_error', and together they equal 'ok' plus GATEWAY_FALLBACK_REASONS (Pitfall 13: refused requests never create ledger rows). Both paths UPSERT the same (day, 'server_error') jev_daily row.
- `recordAggregateOnly(db, {dayUtc, outcome})`: one UPSERT incrementing requests only, for an outcome in AGGREGATE_ONLY_OUTCOMES (TypeError otherwise); dayUtc must match `^\d{4}-\d{2}-\d{2}$`. jev_daily therefore holds at most 18 rows per UTC day ('ok' plus the 17 gateway reasons), whatever the request volume (Pitfall 13).
- `todaySpendUsd(db, dayUtc)` -> SUM(cap_accrued_usd) for the day (0 when none).
- `pruneJevLedger(db, nowMs)`: deletes jev_decisions with created_at < nowMs - 7 days and jev_daily with day_utc < the UTC day 365 days before nowMs.
- `dayUtcKey(ms)`; `LEDGER_COLUMNS` (frozen list of jev_decisions column names); `formatDecisionLog(row)` -> the single allowlisted log string `'[jev] decision ' + JSON.stringify({decisionId, outcome, kinds, elements, bytes, servedModel, calibration, inputTokens, usageSource, costUsd, costSource, upstreamMs, gatewayMs, upstreamStatus, hashKeyPresent})` built from a fixed key list (unknown row keys never appear).
- Prepared statements are cached per db in a WeakMap (precedent: `telemetry-rate-limit.js` statement cache), not added to `Queries`.

report.js API: `buildReport(db, {days = 7, nowMs = Date.now()})` -> `{days:[{dayUtc, requests, byOutcome:{...}, inputTokensKnown, inputTokensUnavailable, costProviderUsd, costEstimateUsd, costUnavailable, capAccruedUsd}], servedModels:[{servedModel, n, calibration:{status:n}}]}`; `runCli(argv, {db, out, err} = {})` -> exit code; flags `--days N` (1..365), `--recent N` (1..200; lists the N newest jev_decisions rows, newest first, through `buildRecent(db, {limit})`, one line per row holding only decisionId, ISO created time, outcome, servedModel, instrumentVersion, calibrationStatus, kinds, elementCount, requestBytes, inputTokens with usageSource, costUsd with costSource, upstream and gateway latency, upstreamStatus and hashKeyPresent) and `--db PATH`; without an injected db it opens `--db`, else `process.env.DB_PATH`, else `path.join(__dirname, '..', '..', 'fsb-data.db')` with `{readonly:true, fileMustExist:true}`; prints one header line and one line per day and per served model; on any error prints a fixed message `jev-report: failed` to err and returns 1 (never an error message). Main guard: `if (require.main === module) process.exitCode = runCli(process.argv.slice(2));`.
