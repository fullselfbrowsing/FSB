# Phase 67 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Source: `67-RESEARCH.md` → `## Validation Architecture`, and `67-CONTEXT.md` D-01..D-32.
> Task ids are `67-NN-TT` (plan NN, task TT) from the 13 plans written 2026-10-15; the requirement key stays in the Requirement column. Plan 67-13 registers all 14 suite commands in one commit.
> Validation deferral policy (STATE.md → "v1.0.0-specific decisions", owner direction 2026-10-15): every Phase 67 plan is `autonomous: true` and has no `checkpoint:*` tasks. Everything that needs the operator, a live credential, production, real spend or a human eye is listed under "Manual-Only Verifications" and deferred to the milestone-end Validation Block. Nothing here is a task.

## Sampling Rate

- **After every task commit:** run the task's `<automated>` command. Also run every pinned suite whose file the task touched:

  | File touched | Also run |
  |---|---|
  | `extension/background.js` | `node tests/lattice-provider-bridge-smoke.test.js` (both `importScripts` pins move in the same commit), plus the 23 other registered suites that read `background.js` source, listed in 67-11 Task 1's verify line |
  | `showcase/server/server.js` or `src/middleware/global-json-parser.js` | `server-trust-proxy`, `showcase-build-smoke`, `server-ws-phantomstream-relay-compat`, `showcase-route-fallback`, `server-telemetry-body-cap`, `server-telemetry-parser-rate-limit` |
  | `src/telemetry/housekeeper.js` | `server-telemetry-housekeeper` |
  | `src/db/schema.js` or `src/db/queries.js` | `server-telemetry-housekeeper`, `server-telemetry-body-cap`, plus a grep of `tests/` for `.match(/`, `readFileSync` and `sha256(` pins on the file |
  | anything under `showcase/server/src/` | `server-no-ip-leak` |
  | `package.json` `test` chain | `delegation-phase-contract` |

- **After every plan wave:** run all `tests/jev-*` suites. Once the registration plan has landed, also run `node tests/delegation-phase-contract.test.js`.
- **Sweep rules (every regression sweep: 67-09 Task 2, 67-11 Task 1, 67-13 Tasks 1 and 2):** run it in the background and wait for it; never use the `timeout` command; a BASELINE sweep may exit non-zero by design (pre-existing failures are recorded, never 'fixed'); after any sweep that selects `tests/showcase-build-smoke.test.js`, restore `showcase/angular/public/{llms.txt,llms-full.txt,sitemap.xml}` and confirm `git status --short showcase/angular/public` is empty before committing.
- **Before `/gsd-verify-work`:**
  - `npm run validate:extension && npm test` is green under CI conditions (Node 20, port 7225 free). A red `EADDRINUSE` means the chain stopped early; it is not a pass.
  - Then restore `showcase/angular/public/{llms.txt,llms-full.txt,sitemap.xml}`; their date churn is never committed.
  - The compatibility audit (row ALL-c) is clean.
- **Max feedback latency:** 30 seconds per task check.
