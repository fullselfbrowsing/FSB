Use one explicit Phase 57 context-admission matrix in the runtime, composer, and Plan 57-05 shell:
1. Exact verified supported folder/document context + admitted current Phase 57 projection authority + usable result → compose and render `folder` or `reading`. A current admitted D-10 `review-required` reading result is usable but non-definitive and stays in this row.
2. Exact verified supported folder/document context + admitted current Phase 57 projection authority + closed, incomplete, inaccessible/unavailable, stale, ambiguous, or conflicting projection result → synchronously withdraw stale model/action/rail state, then compose and render the anchored neutral `contract-closed` blocker with `Skopeo can’t verify this contract view. `contract-closed` is never a generic fallback for matrix row 3. Geometry safety is part of render admission and must come from the existing certified context/shell geometry path, never from filenames, page text, visual placement guesses, or a stale certificate.

Plan 57-05 adds the production shell method `renderContractView(model, onAction)`. Until that plan lands, tests use the existing shell injection seam with a fake implementing this exact signature; runtime must feature-detect the method and retain no detached DOM fallback.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| background projection → content composer | A privileged bounded envelope enters page-adjacent deterministic code. |
| host page → Shadow DOM shell | Hostile DOM/CSS and metadata surround, but must not influence, the contract model. |
| content runtime → background action | An opaque action ID crosses back to the privileged controller. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-01 | Spoofing | Runtime activation | mitigate | Render requests originate only from current explicit verified corpus/entity state and carry the complete public authority tuple. |
| T-57-03 | Information Disclosure | Composer model | mitigate | Closed schema, hard caps, forbidden-key tests, and text-only metadata exclude IDs, URLs, page content, and raw truth. |
| T-57-04 | Elevation of Privilege | Content action callback | mitigate | Callback accepts only a current opaque action ID; content cannot construct URLs or access storage/provider APIs. |
| T-57-05 | Repudiation | Content lifecycle | mitigate | Stable closed-state reason codes and deterministic state transitions make withdrawal/rejection outcomes testable without sensitive logs. |
| T-57-06 | Denial of Service | Model composition | mitigate | Frozen caps, bounded strings, local eight-row paging, and stale-result dropping bound work and retained state. |
| T-57-07 | Tampering | Host metadata/CSS | mitigate | Strings remain text, arbitrary blocks/HTML are rejected, and the existing Shadow boundary remains the sole render target. |
| T-57-08 | Tampering | Async lifecycle | mitigate | Synchronous withdrawal/action-epoch increment precedes replacement; every async return rechecks all currentness dimensions. |
| T-57-SC | Tampering | npm/pip/cargo installs | mitigate | No package installation occurs; the existing dependency set and lockfiles remain unchanged. |
</threat_model>
