## Sampling Rate

- **After every task commit:**
  - Run the task's `<automated>` command.
  - Run the pin suites for every file the task edits (table below; CONTEXT D-24, RESEARCH "Project Constraints"). Before editing any listed file, grep `tests/` for `.match(`, `.includes(`, `indexOf(`, `readFileSync` and `sha256(` pins on it, and bump paired pins in the same commit.
  - For edits to `background.js`, `agent-loop.js`, `options.js`, `config.js`, `control_panel.html`, `mcp-tool-dispatcher.js` or `messaging.js`, also run the regression sweep against the Wave 0 baseline (in the background, waited for).
  - Whenever `package.json` changes: `node tests/delegation-phase-contract.test.js`.
- **After every plan wave:**
  - Run every `tests/jev-*` suite present so far (Phase 67's and Phase 68's), the 66.1 settings suites (`settings-schema`, `settings-panel-sync`, `mcp-settings-route`, `mcp-settings-tool-contract`), `tests/showcase-privacy-page.test.js` and `node tests/jev-policy-tighten-only.test.js`.
  - Run each new Phase 68 suite once more under `npx --offline -y node@20`.
  - Run the regression sweep over every file edited in the wave.
- **Before `/gsd-verify-work` (phase gate):**
  - `npm run validate:extension && npm test` is green under CI conditions (Node 20 for the new suites; run in the background and waited for, since it can exceed the 10-minute foreground limit).
  - The showcase i18n gates above are green (execution tree).
  - The D-24 pin audit (row `ALL-a`) and the compatibility audit (row `ALL-c`) are clean.
  - The three showcase crawler files are restored.
- **Max feedback latency:** 30 seconds per task check. Pin bundles that would push a task's `<automated>` command past 30 s run once in the plan's wave gate in `<verification>`, and the SUMMARY records each exit.
