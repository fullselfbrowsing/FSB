Every phase of v1.0.0 (66, 66.1, 67, 68, 69, 70, 71) is code-complete and verified with automated checks only. **Precedence.** If this runbook and a phase's VALIDATION row disagree, the VALIDATION row wins. For every `M-71-*` row, `71-VALIDATION.md` "Manual-Only Verifications" is authoritative. Where 71 supersedes 66-10 or 66-11 (rounds, run counts, browser, Claude binary, approval order), the 71 row wins.

## Conventions and stop rules

- **Order.** Section 1 decisions first, then V1 → V2 → V3 → V4 → V5 → V6. Some V5 items can run early; each says when.
- **Two working trees.** V1 runs in a pin worktree at `8a058bdf`: `PIN="$HOME/.fsb-bench/pin-8a058bdf"`. Everything else runs on the Jev branch: `JEV=/Users/lakshman/conductor/workspaces/fsb/astana`. Keep both out of `/tmp`.
- **Nothing reaches `main` before V6.** A push to `main` runs `deploy.yml` (Fly), `chrome-extension.yml` (packaging) and `npm-publish.yml`. Before V6, production is touched only by `flyctl deploy` from Jev and by `fly secrets set`. Never push `main`, and never push the pin worktree's local branch.
- **Code freezes at the V4 release-candidate SHA (D-24).** After that SHA is fixed, only docs-class paths may change without a re-measure: `*.md`, `.planning/**`, `showcase/**` outside `showcase/server/**`, `skills/**`, `store-assets/**`, `scripts/bench/results/**` and `scripts/bench/gate/decisions/**`. A V5 finding that needs a code fix is a re-measure decision for the owner, never a waiver.
- **No commits on Jev from the first V4 campaign start until M-71-08 finishes.** The campaigns record `git.sha`, and the evaluator refuses a tree that differs from the measured SHA.
- **Notes.** Record evidence in `~/.fsb-bench/notes/v1.0.0-validation-notes.md`, with one `## Vn` section each. It stays outside the repo until V4's decision commit lands. Then copy it to `.planning/v1.0.0-VALIDATION-NOTES.md` and commit it as a separate docs commit. Only a human run may change a `result:` field in a `*-HUMAN-UAT.md`.
- **Commits.** Use conventional single-line subjects with no AI attribution. Stage explicit paths only. After any full test run, restore the crawler churn with `git checkout -- showcase/angular/public/llms.txt showcase/angular/public/llms-full.txt showcase/angular/public/sitemap.xml`.
- **Ports.** The bench needs 7225 owned by the runner. The human stops whatever holds 7225 or 7226 (the everyday hub, Claude Desktop, other sessions' fsb servers, the 7226 native-host daemon), or authorizes exact PIDs. Automation never kills unlisted user processes.
- **Same instrument from V1 to V4.** Use the same Claude Code binary, Claude model, Chrome for Testing major, xAI model `grok-4.3` and terminal profile. The gate compares `hosts.claude.envKeyNamesSha256`, so do not add or remove environment variables between V1 and V4.
- **Resuming a campaign.** After exit 75, run the exact `run-bench: resume with: …` command the runner prints. After a Ctrl-C, rerun the original command with `--campaign-id <id>` replaced by `--resume <id>`. Never run a bare `--resume <id>`: it rebuilds the schedule at the default 10 rounds and is refused.
- **Refusals stop the step.** For example `telemetry_not_opted_out`, `dirty_tree`, `gate_campaign_mismatch`, `resume_identity_mismatch`, `corpus_mismatch`, `gate_hash_mismatch`, `gate_not_predeclared` or `uncommitted_changes`. Diagnose the refusal; never work around it. Never pass `--allow-dirty` to a gate campaign.
