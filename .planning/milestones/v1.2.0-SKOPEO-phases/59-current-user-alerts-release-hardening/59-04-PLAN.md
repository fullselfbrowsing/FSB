# Plan 59-04 — Golden Corpus and Adversarial Release Evaluation

## Objective

Create the versioned deterministic gold/adversarial corpus, register one release aggregate, and create the honest human/live evidence ledger without promoting synthetic results.

## Task 1 — Controlled RED gold manifest and aggregate

Create:

- `tests/fixtures/skopeo-release-evals/manifest.json`
- `tests/fixtures/skopeo-release-evals/cases.json`
- `tests/skopeo-release-evals.test.js`

The manifest maps every Phase 59 requirement and T59 threat to at least one case and fixes expected source paths/roles, dates, window calculations, delivery method/address, consequence, owner mapping, alert date, Document 10/memo state, and forbidden disclosure fields. Controlled RED asserts missing production/eval registration with one exact marker.

## Task 2 — Implement full gold and adversarial matrix

Complete cases for active agreement, partial amendment, full replacement, unsigned draft, conflicting fact, unreadable scan, inaccessible source, Document 10, complex memo present/missing, near notice deadline, and permission-negative abstention. Add prompt injection, malicious filename, fake citation, cross-vendor exfiltration, source replacement/deletion/revocation, duplicate alarm/notification, delayed wake, stale click, and repeated lifecycle/virtualization negatives.

The aggregate executes production schema/engine/store/runtime/HUD modules and reports deterministic gold, structural security, lifecycle browser/provisional, domain fidelity, authorized live Drive/Docs/PDF, and human accessibility separately.

## Task 3 — Register release gate and human UAT ledger

Create `.planning/milestones/v1.2.0-SKOPEO-phases/59-current-user-alerts-release-hardening/59-HUMAN-UAT.md`. Modify `package.json` and dependent order assertions to register `test:skopeo-release-evals` exactly once after Ask/HUD/truth prerequisites. The human ledger keeps Docs, text PDF, blocked download, shared access, revocation, account switching, native notification, legal/domain, VoiceOver, density, and host-coexistence rows `human_needed`/`live_approved:false` until observed.

**Gate:** release eval, truth/HUD/Ask aggregates, storage boundary, and package-order regressions green.

## Must-Haves

- Gold expected values are explicit and versioned, not derived by the implementation under test.
- Permission-negative cases assert absence of source existence and derived information.
- Synthetic/local-browser evidence cannot change legal/live/human approval fields.
- Unsupported PDF/scan/download behavior is recorded, never guessed.
