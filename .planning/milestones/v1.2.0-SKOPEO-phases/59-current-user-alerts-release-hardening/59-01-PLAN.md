# Plan 59-01 — Closed Alert Foundation and Durable Ownership

## Objective

Create the exact alert data contract, durable partitioned owner/ledger store, real corpus `alerts` purge participant, and pure notice-only 90-day eligibility/state engine. No Chrome alarm or notification effect exists in this plan.

- `tests/skopeo-alert-schema.test.js`

Add exact controlled-RED switches and source markers proving the three production modules do not yet exist. **Gate:** controlled RED markers pass exactly once; test files syntax-check.

## Task 2 — Implement closed schema and pure alert engine

Create:

- `extension/utils/skopeo-alert-schema.js`
- `extension/utils/skopeo-alert-engine.js`

Use classic IIFE/CommonJS dual exports, exact enumerable own-data parsers, bounded scalar-safe text, null-prototype rebuilt records, recursive freeze, finite caps, and distinct private/public models. The engine must:

- accept only one exact eligible governing `notice-deadline` with current/exact inputs, consequence, timezone, governing citation, complete sources, and one current owner relation;
- compute `deadlineCivilDate - 90` through injected deadline-engine ordinals;
- decide mapped/not-locally-deliverable without label/email matching;
- build deterministic digest material and validate scheduled/attempted/delivered/failed/missed/superseded transitions;
- produce a minimized public status with no stable/account/source/revision/alert/alarm IDs.

**Gate:** schema and engine tests green plus `node --check`.

- Storage read failure/malformed state cannot initialize-and-overwrite.

- No alarms, notifications, HUD, content, MCP, telemetry, or provider effect is introduced.
