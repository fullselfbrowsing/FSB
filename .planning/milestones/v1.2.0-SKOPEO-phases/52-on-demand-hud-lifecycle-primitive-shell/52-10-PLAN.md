<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Chrome tab ID to controller activation | A reused numeric tab ID is not proof that old asynchronous work is current. |
| Async response to side-panel DOM/global state | Every success/rejection is untrusted after its activation or request lane expires. |
| Runtime status event to lifecycle presentation | Tab ID alone is insufficient; a lower or unverifiable generation can regress current state. |
| Side-panel Skopeo row to unrelated chat UI | Authority handling must not retarget chat content, focus, or existing automation state. |

| Stale resurrection / state regression | High | mitigate in Tasks 1-2 | Expired activations cannot render; per-tab positive generation floors reject delayed lower-generation responses/events. |
| Host interaction interception | High | preserve / owned by Plan 52-09 | This plan changes no content shell; local-Chrome geometry gate remains in the Phase 52 chain. |
| Focus denial or unrelated UI corruption | High | mitigate/preserve in Task 1 | Zero-write stale cases and exact side-panel focus/chat snapshots prove Skopeo authority work stays bounded to the current row. |
