# Phase 53.1 Plan 11: Same-Document Route Sequencing Summary

**Same-document route replies are now newest-wins per tab and controller generation, with obsolete completions unable to alter the current session or invoke terminal cleanup**

## Accomplishments

- Added a controlled production regression that sends two route notifications through `tabs.onUpdated`, resolves epoch 3 before epoch 2, and proves the older reply is fully inert across projection, authority, tokens, gate state, storage, broadcasts, and termination messages.
- Added inverse-order, per-tab isolation, controller replacement, explicit kill, hard-navigation, and origin-change cases, plus an in-memory weakened-currentness control that fails for the intended obsolete-reply reason.
- Added synchronous controller-local route sequence capture and bound requests to tab, controller identity, generation, admitted origin, sequence, and lane version.
- Moved projection replacement, authority advancement, token clearing, pending-state invalidation, and route-derived cleanup behind a controller-local commit lane with repeated currentness checks.
- Preserved terminal precedence by closing outstanding route work before replacement, termination, hard navigation, origin cleanup, or tab removal.

## Decisions Made

- Dispatch both admitted same-origin route requests without a preliminary storage await so the real two-reply completion race remains possible; the stored Active record is checked inside the guarded commit lane before any route-derived mutation.
- Treat route sequence and lane metadata as controller-generation state rather than global state, preserving independence across tabs and replacements.
- Return `false` for obsolete route work without stale-runtime or missing-runtime classification, since an obsolete reply has no authority to clean up the current session.
- Keep terminal transitions closed for an existing controller entry: once its lane is invalidated, that controller cannot admit later same-document commits.
