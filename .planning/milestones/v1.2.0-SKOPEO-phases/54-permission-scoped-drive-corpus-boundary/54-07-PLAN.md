<interfaces>
Content sends only an exact message claim such as:
```text
skopeo:corpus-enroll {
  generation, exactOrigin, profileVersion, contextEpoch,
  semanticEntityToken, corpusRootFileId
}
skopeo:corpus-status {
  generation, exactOrigin, profileVersion, contextEpoch,
  semanticEntityToken, currentSourceFileId?
}
```
All fields are non-authoritative and background re-derives the live tuple/root/account/source. Content accepts only one of these closed projection families, bound to its current tuple/action token:
```text
{ mode:"current-source", state:<six-state>, labelToken:"current-source", actionToken }
{ mode:"active-corpus", rows:[{ rowToken, state, displayLabel? }], aggregate?, actionToken }
{ mode:"corpus-closed", reasonCode, actionToken }
```
`current-source` is used for the exact current Drive file/Docs semantic entity. If its identity/name is unsafe because proof is unavailable/denied, `labelToken:"current-source"` is local generic copy and no source ID/name/row/count is present. `active-corpus.rows` contains only sources freshly certified for the same bounded display operation; `rowToken` is an ephemeral locally owned projection token, never a Drive ID. `displayLabel` is optional and present only when freshly certified display-safe. `aggregate` is allowed only if every contributor is one of those same-operation certified rows and all remain current through final assembly; otherwise it is omitted. Any unproven, pending, inaccessible, missing, or fail-quiet projection with unavailable/denied current proof structurally forbids `rows`, `aggregate`, and `sourceStateCounts`, and prior values are withdrawn before paint. Permission IDs, certificates, Drive/change/page/resource tokens, raw errors, content, excerpts, relationships, answers, citations, and future graph/index intelligence are always forbidden.
</interfaces>
