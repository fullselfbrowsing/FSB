<interfaces>
The registry is a frozen classic-script/CommonJS module:

```javascript
const registry = FSBSkopeoAnchorRegistry.createRegistry({
  generation,
  signal,
  window,
  document,
  observationRoot,
  resourceLedger,
  resolveCandidates,   // trusted adapter callback; receives closed locator records
  validateCandidate,   // trusted adapter callback; returns exact semantic proof
  isCurrent,           // ({generation,contextEpoch,semanticIdentity,bindingEpoch}) -> boolean
  onWithdraw,          // synchronous visual callback
  onCommit             // receives validated projection only
});

registry.setContext({ generation, contextEpoch });
registry.register(descriptor);
registry.resolve(anchorId);
registry.signal(kind); // mutation | scroll | resize | zoom | navigation
registry.withdraw(anchorId, reason);
registry.dispose();
registry.getSnapshot();
```

Exact descriptor:

```javascript
{
  anchorId,
  contextEpoch,
  semanticIdentity:{kind:'drive-folder'|'drive-file'|'docs-document'|'opaque-target',id},
  candidateLocators:[{kind:'drive-item-id'|'docs-document-id'|'opaque-target-key',value}],
  validators:['semantic-identity','connected','geometry']
}
```

No descriptor contains a CSS selector, page label, function, Node, Range, HTML, or host content. Resolvers return candidate objects; the registry alone owns the mutable binding and `bindingEpoch`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Immutable descriptor → live DOM adapter | Closed stable IDs/locator keys authorize candidate checks; nodes/ranges remain revocable untrusted bindings. |
| Host mutation/geometry → registry | Recycled nodes, forged attributes, detached ranges, and rectangles can change between every check. |
| Async resolver → visual callback | Completion is hostile to time/order; only the full current authority tuple may cross to commit. |
| Registry resources → Phase 52 lifecycle | Observers/listeners/frames/pending work must be bounded, owned, abortable, and exactly released. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-02-01 | Spoofing | candidate semantic validator | mitigate | Exact stable-ID comparison independent of node identity; paired file-A/file-B and hostile candidate tests. |
| T-53-02-02 | Tampering | DOM node/Range reuse including ABA | mitigate | Binding epoch invalidation, synchronous withdrawal, fresh resolution, and final identity/connection proof. |
| T-53-02-03 | Elevation of privilege | forged generation/context/identity/binding tuple | mitigate | Registry-owned epochs plus injected current-authority predicate after every await and at final side effect. |
| T-53-02-04 | Denial of service | broad observation/resource exhaustion | mitigate | Injected narrow root, one observer/frame, bounded locators, coalescing, AbortSignal, and exact resource ledger teardown. |
| T-53-02-05 | Information disclosure | descriptor/callback diagnostics | mitigate | No page text/selector/content logging or persistence; projections contain only identity metadata and rectangle. |
| T-53-02-06 | Tampering | teardown resurrection | mitigate | Dispose invalidates epochs before cancellation/removal; delayed callbacks check terminal/abort and cannot commit. |
