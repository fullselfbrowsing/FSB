<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host URL/page hints → router | URL strings and all visible/DOM-derived values are hostile and cannot establish semantic identity. |
| Trusted caller identity → closed result | Even caller data must match exact keys, kinds, bounds, origin, and corroborating ID before recognition. |
| Route evaluation → downstream shell/registry | Only frozen closed vocabularies and metadata may cross; no host copy, selector, HTML, or permission claim. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01-01 | Spoofing | exact-origin parser | mitigate | `URL.origin` equality for two allowlisted origins; near-neighbor/http/restricted negatives fail unsupported. |
| T-53-01-02 | Tampering | route/evidence envelopes | mitigate | Exact own-key schemas, frozen closed vocabularies, bounded IDs/evidence, and rejection of unknown fields. |
| T-53-01-03 | Information disclosure | result/diagnostic evidence | mitigate | Emit only stable ID/type/reason metadata; tests reject page names, text, URLs, and hostile payload echoes. |
| T-53-01-04 | Elevation of privilege | configured-corpus/vendor recognition | mitigate | URL/name/position/class/shape alone never recognizes; stable trusted identity plus corroborating route evidence is mandatory. |
| T-53-01-05 | Denial of service | oversized/adversarial input | mitigate | Hard URL/ID/evidence bounds, finite array cap, no DOM traversal/network work, and terminal dispose/epoch overflow failure. |
</threat_model>
