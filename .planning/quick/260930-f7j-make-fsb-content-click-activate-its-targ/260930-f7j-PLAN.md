# Quick 260930-f7j: Make FSB content click activate its target once

## Why

FSB's content-script `click` fired every target twice. The `click` tool dispatched a synthetic `mousedown`/`mouseup`/`click` sequence and then unconditionally called `element.click()`. `clickAtCoordinates` did the same and then always sent a trusted CDP click.

The effects:
- Toggles, checkboxes and switches flipped twice and ended unchanged.
- Forms submitted twice.
- Verification then saw no effect, and the CDP fallback activated the target a third time.

The `element.click()` call was never a deliberate fallback. Commit fc584605 placed the synthetic sequence in front of the older call and relabelled it.

Found by Phase 66 plan 66-07 while building the benchmark corpus. See `.planning/phases/66-baseline-and-session-timing/deferred-items.md`. The fix lands before the Phase 66 live baseline, so the baseline measures a single-activation click.

## Tasks

### Task 1: Single activation and toggle-aware verification in actions.js

**Files:** `extension/content/actions.js`

**Action:**
1. **Helpers.** After the `// ACTION VERIFICATION UTILITIES` banner, add:
   - `TOGGLE_STATE_ATTRIBUTES`;
   - `getAssociatedStateElement(element)`. It walks the element and up to 5 parents and returns the first match:
     - a label's control, unless the control is the target itself;
     - a summary's details;
     - a toggle-like ancestor.
   - `describeToggleState(el)`, which joins checked, open, the toggle ARIA attributes and data-state.
2. **`captureActionState`:** add `controlState`.
3. **`detectChanges`:** add `innerTextChanged` and `controlStateChanged`, both false when the element is gone.
4. **`EXPECTED_EFFECTS.click.anyOf`:** add `checkedChanged`, `controlStateChanged`, `ariaCheckedChanged`, `ariaPressedChanged`, `ariaSelectedChanged`, `dataStateChanged`, `openChanged` and `innerTextChanged`.
5. **`verifyActionEffect`:** add `localChanges` entries for pressed, selected, checked and control-state changes.
6. **Click tool:**
   - add `composed: true`;
   - remove the `element.click()` after the synthetic dispatch;
   - compute `toggledState` and add it to the anchor branch of `hadEffect`.
7. **`clickAtCoordinates`:**
   - capture `preState`;
   - add `composed: true`;
   - remove `element.click()`;
   - verify after the stability wait;
   - send `cdpMouseClick` only `if (!verification.verified)`;
   - return `hadEffect`.

**Verify:**
- `node --check extension/content/actions.js`
- The one-off headless harness (uncommitted, in `/tmp/fsb-click-harness`) loads `CONTENT_SCRIPT_FILES` into an isolated world and calls `FSB.tools.click`. Each target must activate exactly once, and toggles must end flipped.

**Done:** The click paths activate once, and toggle-only effects verify without the CDP fallback.
