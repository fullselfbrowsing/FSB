### 1. Build the action-icon module

**Files:** `extension/utils/action-icon.js` (new)

**Action:**
Create a self-contained classic-script IIFE that assigns a frozen object to
`globalThis.fsbActionIcon`. The file must live in `extension/utils/` — `scripts/validate-extension.mjs:123`
syntax-checks that directory (tripwire 8). No ESM, no `export`, no top-level `await`.

Public API (this is the contract Task 2 wires against — define it exactly):

- `init(options)` — async, idempotent. `options.hasLiveSession` is an optional `() => boolean`
  probe. Guards: if `typeof OffscreenCanvas === 'undefined'`, `typeof createImageBitmap !== 'function'`,
  or `chrome.action?.setIcon` is missing, set an internal `unavailable` flag and return silently —
  every other method then becomes a no-op. Otherwise build the frame cache, read persisted
  intent, and apply the derived frame.
- `applyOverlayState(overlayState)` — the single drive point. Maps and dispatches (see below).
- `setWatching(isWatching)` — boolean; static frame only, no loop.
- `setConnected(isConnected)` — updates the idle-frame strength.
- `repair()` — watchdog entry point; re-derives and re-applies the current frame, restarting
  the loop if intent says animating but no interval is live.

Base glyph: `fetch(chrome.runtime.getURL('assets/icon128.png'))` → `.blob()` → `createImageBitmap()`
→ `drawImage` scaled down, then call `.close()` on the bitmap. Do NOT rasterize SVG —
`createImageBitmap` rejects SVG sources in a service worker. `assets/icon128.png` is 128×128
and already exists; do not touch `manifest.icons` paths (tripwire 9).

Canvas: one reused `OffscreenCanvas` per size, context obtained with
`getContext('2d', { willReadFrequently: true })`. Without that flag every `getImageData()`
forces a GPU→CPU readback.

Frame composition, per size, per frame:
1. `clearRect` the whole canvas. **Never** fill `#000000` — the background stays transparent
   (a black box on dark toolbars is unfixable; `matchMedia` is not exposed in
   `ServiceWorkerGlobalScope` and Chrome does not support `theme_icons`).
2. Draw the base glyph centered at `GLYPH_SCALE`. For the disconnected idle frame only,
   set `ctx.globalAlpha = DIM_ALPHA` and `ctx.filter = DIM_FILTER` first, then reset both
   to `1` / `'none'`.
3. For animated and watching frames, stroke the orbit bead: a circular ring centered at
   `size/2` with radius `size/2 - RING_INSET_RATIO*size` and `lineWidth = RING_WIDTH_RATIO*size`,
   `lineCap = 'round'`. The bead spans `BEAD_FRACTION` of the circumference starting at
   `progress`, rendered as `BEAD_SEGMENTS` consecutive sub-arcs; each sub-arc's stroke colour
   is a linear RGB lerp from `glow-color-1` at the bead head to `glow-color-2` at the tail,
   and its alpha ramps 0→1 across the leading `FADE_FRACTION` and 1→0 across the trailing
   `FADE_FRACTION`. Watching uses the same bead frozen at `progress = 0`.
4. `getImageData(0, 0, size, size)` and store.

Emission: always `chrome.action.setIcon({ imageData: { 16: img16, 32: img32 } })`. Never pass
a bare `ImageData` (32 is what Chrome picks on 2x displays) and **never** pass `tabId` —
tab-specific icons permanently shadow global ones, so a global loop would silently stop
updating any tab that ever received a per-tab icon. Swallow the returned promise's rejection.

Loop: `setInterval` at `FRAME_INTERVAL_MS`. `chrome.alarms` has a 30s floor and is unusable
for animation. Frame index each tick is derived from wall clock, not a counter, so the loop
self-corrects: `elapsed = (Date.now() - startTime) % duration`, `progress = elapsed / duration`,
`index = Math.min(frameCount - 1, Math.floor(progress * frameCount))`. Exactly one interval
may exist; starting a loop clears any prior one.

Phase → state map inside `applyOverlayState`, identical to `content/messaging.js:1169-1173`:
gate on `overlayState.highlight && overlayState.highlight.animated` (computed at
`utils/overlay-state.js:442-444` as `animatedHighlights !== false && lifecycle === 'running'`).
If the gate is false, stop the loop and snap to the static frame. If true, map
`overlayState.phase`: `calling` → `calling`; `acting` | `writing` | `switching_tab` → `acting`;
everything else → `thinking`.

Retime on state change — port the progress-fraction preservation from `visual-feedback.js:1197-1205`
so the bead does not jump when the period changes mid-cycle. With `now = Date.now()`:
`elapsed = (now - startTime) % oldDuration`, then `progress = elapsed / oldDuration`, then
`startTime = now - progress * newDuration`. Only apply when a loop is already running;
otherwise set `startTime = now` (fresh cycle from 0).

Persistence + eviction recovery: write intent to `chrome.storage.session` under key
`fsbActionIconIntent` with shape `{ animating, state, watching, connected, updatedAt }` on
every state transition (not every tick). In `init()`, read it back and: if `animating` is true
AND `options.hasLiveSession` is absent or returns true, restart the cycle **from frame 0** —
do NOT resume mid-phase (this is the same as ViewportGlow being destroyed and recreated on a
page reload); if `animating` is true but the probe says no live session exists, snap to the
correct static frame (equivalent to ViewportGlow's `destroy()` on `cleared`). If the SW is
killed mid-animation the icon freezes on the last frame — action state lives in the browser
process, so it does not revert to the manifest default; `repair()` is what unfreezes it.

Comment text is fine in this new file — the token-count tripwires apply to `background.js`
and `ws-client.js`, not here. Do not write the string `importScripts` anywhere in this file.
